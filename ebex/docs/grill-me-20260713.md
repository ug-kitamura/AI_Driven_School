# EBEX — グリル／設計メモ（大きな成果物の書込・非ストリーム制約）

**実施日**: 2026-07-13  
**目的**: 社内ネットワークでストリーム受信できない前提でも、大きな HTML 等の成果物を tool JSON 途切れ／path 欠落で落とさず残す方針を固める  
**きっかけ**: `creating-visual-explainers` 等で HTML が大きいと `必須の path（または from/to）が欠落または空です` が連続し、エージェントが停止する  
**前提**:
- スキル本文は Cursor パリティのため極力変えない（ランタイム側で合わせる）
- 社員利用・多様なスキル。スキル固有の HTML 強制コピーには戻さない
- **社内ネットではストリームでデータを取得できず、応答を待ってまとめて受け取る**
**ステータス**: 方針合意（メモ） / 実装は別セッションで OpenSpec proposal 予定  
**関連**:
- `openspec/changes/ebex-agent-skill-zone-parity`（L1 スキルゾーン、`replace_between` / `append_file`、HTML 強制リカバリ削除）
- `openspec/changes/ebex-agent-history-file-primitives`（`copy_file` / `replace_in_file`）
- `grill-me-20260712.md`（ツール最小セット・確認ゲート・max_tokens）

## 背景

### 何が起きているか

1. モデルが大きな本文を `write_file` / `replace_between(content: …)` 等の **tool 引数 JSON** に載せる
2. 1 回の応答が `max_tokens` 等で途中切れ → JSON 破損、または `path` / `from` / `to` が欠ける
3. ランタイムは壊れた tool_use を実行せず、同じエラーを返す
4. 同一エラーが連続するとセーフティで停止  
   （例: `同一のツールエラーが連続したためエージェントを停止しました: 必須の path（または from/to）が欠落または空です`）

ストリームの有無に関わらず、**「大きな本文を親エージェントの 1 tool_use に載せる」限り再発する**。

### いま入っている緩和（skill-zone-parity まで）

| 手段 | 役割 | 限界 |
|------|------|------|
| L1 でスキル `references/*` を発見 | Step 0 の 0 件落ちを解消 | 書込サイズ問題は別 |
| `copy_file` | テンプレをディスクへ（本文は tool に載せない） | 中身の大きな差し込みは別 |
| `replace_between` + `from_path` | 大きな差し込みをファイル経由に | モデルが巨大 `content` に戻ると死ぬ |
| `append_file`（小さ分割） | partial を複数ターンで積む | **1 chunk が大きすぎると同じ途切れ**。モデル遵守が必要 |
| HTML 強制テンプレコピー | （削除済み） | スキル固有パッチであり、根本ではない |

### 社内ネット制約の含意

```
ストリーム書込（partial_json を受信しながら追記）
        ↓
社内では増分受信できない → 採用しない（またはサーバ↔API 内部に限定）
        ↓
抜本策は「親の tool JSON に大きな本文を載せない」経路
```

localStorage  alone も無効。ボトルネックは保存先ではなく **モデルが本文を出すチャネル**（LLM 応答／tool_use）にある。

## 決まったこと（方針）

### 1. 問題の定義

| 項目 | 決定内容 |
|------|----------|
| **本質** | 大きな成果物を親エージェントの tool 引数に載せること |
| **非本質** | 「JSON vs localStorage」や「ストリーム UI」 alone |
| **制約** | 社内は一括受信。ストリーム依存の救済は主案にしない |

### 2. 責任分担（スキル vs ランタイム）

| 側 | 持つもの | 持たないもの |
|----|----------|--------------|
| **スキル** | 何を作るか・手順・参照（`references/*` 等） | EBEX 固有の巨大書込プロトコルの強制記述（パリティのため） |
| **ランタイム** | 「大きな本文を親 tool JSON に載せない」汎用経路 | 特定スキル名分岐・HTML 専用強制コピーの復活 |

合意の言い方:

> スキルが指示し、**ランタイムが大きな書き込みを肩代わりできる道具を差し出す**。  
> スキル固有ロジックで HTML を強制する旧リカバリには戻さない。

### 3. 非ストリーム前提の候補と優先

| 優先 | 案 | 概要 | 社内一括受信 |
|------|----|------|----------------|
| **主** | **サーバ内生成 → 直書き** | 親 tool は小さい指示（path・何を書くか）。サーバが別 LLM 呼び出し（`stream: false` 可）し、**本文はサーバがファイルへ書く**。親へ返すのは path / bytes 等の要約のみ | ✅ 適合 |
| **輔** | **小さ分割 append → replace_between(from_path)** | 現行 primitive の運用。チャンクが小さい必要あり | ✅ 遅いが可 |
| **図解向け抜本** | **構造化スロット＋サーバ組立** | モデルは短い JSON のみ。HTML はテンプレ／サーバが組立 | ✅ 適合 |
| **不採用（主案）** | ストリーム書込 | 受信中に追記 | ❌ 社内制約と非適合 |
| **誤診** | localStorage  alone | UI 下書き以外ではチャネルが変わらない | — |

### 4. サーバ直書きのイメージ（未実装・提案レベル）

親エージェントが呼ぶイメージ（名前は仮）:

```
generate_and_write / write_generated
  path: workspace 相対
  instruction: 短い指示（セクション内容・トピック等）
  （任意）from_template / markers / mode
```

挙動:

1. ランタイムが別 LLM ターンを実行（一括受信可）
2. 得られた本文をサーバが対象 path に書く（または partial に書く）
3. tool_result は要約のみ（本文を履歴に戻さない — `grill-me-20260712` の規律と一致）
4. 確認ゲートは既存の上書き／プロジェクト外規則に乗せる

親の tool_use には **巨大 HTML が乗らない**。

### 5. 既存 primitive との関係

| 既存 | 位置づけ |
|------|----------|
| `copy_file` | テンプレ配置の正攻法（継続） |
| `replace_between` + `from_path` | ディスク上の大きな塊の差し込み（継続） |
| `append_file` | 小さな塊の積み上げ、またはサーバ直書きの補助 |
| `write_file` | **短いファイル向き**。大きな成果物の本命にしない（案内で明示し続ける） |

### 6. やらないこと（本メモ時点）

- `creating-visual-explainers` / `minutes-maid` の SKILL.md 改変を前提にした解決
- HTML 専用 `template-write-recovery` の復活
- ストリーム必須の設計を社内本番の前提にすること
- max_tokens 引き上げ alone を根本対策とすること

## 関連メモ

- 停止メッセージの直接原因: `isBrokenToolUse` → `AGENT_MISSING_PATH_ERROR` の連続（`MAX_CONSECUTIVE_IDENTICAL_TOOL_ERRORS`）
- 壊れた tool_use 時の案内: `LARGE_FILE_WRITE_GUIDANCE`（copy / replace_between+from_path / append）
- 図解テンプレは `<!-- CONTENT_START -->` / `<!-- CONTENT_END -->`（`replace_between` 向き）
- 受け入れ済み（parity）: 実スキル `creating-visual-explainers` で `references/*` glob → copy → replace_between の経路は単体レベルで確認済み。巨大本文の安定生成は未解決
- 参照: `lib/agent/agent-loop.ts`、`lib/agent/tools/registry.ts`、`lib/agent/llm/types.ts`
