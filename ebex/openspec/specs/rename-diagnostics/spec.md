# rename-diagnostics Specification

## Purpose
フォルダリネーム失敗時の自動診断記録（基本情報・ロックプローブ・対照テスト）の要件。
## Requirements

### Requirement: リネーム失敗の自動診断記録
フォルダリネーム（`renameFolder`）が失敗した場合、システムは診断情報を `.meta/diagnostics.log` へ JSON Lines 形式で追記しなければならない（SHALL）。診断記録には以下を含めなければならない（MUST）: タイムスタンプ、エラーコード（EPERM 等）、from/to の絶対パスとパス長、リネーム先の存在チェック結果（大文字小文字を無視した衝突判定を含む）。

#### Scenario: 失敗時に基本情報が記録される
- **WHEN** フォルダリネームが EPERM で失敗する
- **THEN** diagnostics.log にエラーコード・パス情報・衝突判定を含むレコードが 1 行追記される

#### Scenario: 成功時は記録しない
- **WHEN** フォルダリネームが成功する
- **THEN** diagnostics.log には何も追記されない

### Requirement: ロック元ファイルのプローブ
リネーム失敗時、システムは対象フォルダ配下の各ファイルを同一ディレクトリ内の一時名へリネームして即座に戻すプローブを実行し、プローブに失敗したファイル（＝ロック元候補）の一覧を診断記録に含めなければならない（SHALL）。プローブの失敗自体がユーザー操作を妨げてはならない（MUST NOT）。

#### Scenario: ロック元の特定
- **WHEN** 外部プロセスがフォルダ内の特定ファイルのハンドルを保持した状態でリネームが失敗する
- **THEN** diagnostics.log のレコードにロックされたファイルのパスが列挙される

### Requirement: 環境切り分けの対照テスト
リネーム失敗時、システムは同じ親ディレクトリに一時フォルダを新規作成して即リネームする対照テストを実行し、その成否を診断記録に含めなければならない（SHALL）。テスト用の一時フォルダは実行後に削除しなければならない（MUST）。

#### Scenario: 環境全体の問題の検出
- **WHEN** 対象フォルダのリネームが失敗し、新規一時フォルダのリネームも失敗する
- **THEN** 診断記録から「環境全体でリネームが阻害されている（EDR ポリシー等）」と判断できる

#### Scenario: フォルダ固有の問題の検出
- **WHEN** 対象フォルダのリネームが失敗し、新規一時フォルダのリネームは成功する
- **THEN** 診断記録から「対象フォルダ固有のロックが原因」と判断できる

### Requirement: ユーザーへのエラー提示
リネーム失敗時、UI にはエラーコードと「診断情報を記録した」旨を含むメッセージを表示しなければならない（SHALL）。診断処理の実行によりエラー表示が既存動作から遅延・欠落してはならない（MUST NOT）。

#### Scenario: 失敗の通知
- **WHEN** Pane 1 でのフォルダリネームが失敗する
- **THEN** エラーメッセージにエラーコードが含まれ、診断ログの記録が案内される
