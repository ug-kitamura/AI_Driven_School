# 出力品質チェックリスト

提案文を出力する前に、以下を満たすか確認する。満たさない項目は直してから出力する。

## 結論と構造

- [ ] 1行目が結論（＝相手へのお願い）になっている。要約で終わらず「だから何をしてほしいか」まで言い切っている
- [ ] 各言語版が内容行15〜20行以内（空行は数えない）
- [ ] 構成が「結論 → コスト vs ベネフィット → 現状 → 推奨 → リスク」の順になっている
- [ ] 事実・解釈・提案が混ざらず分かれている
- [ ] 情報が階層構造（■ → ◎ → ・）で整理されている（英語版は `-` バレット）
- [ ] 選択肢は1〜3案、各案1行、`→推奨` を明示している

## パーパス整合

- [ ] `references/company-purpose.md` を参照し、提案全体がパーパス10項目と矛盾しない
- [ ] 特定項目への言及は自然な接点があるときだけ（くどくない）
- [ ] 独立したパーパスセクションを作っていない

## 日英

- [ ] 生成順序が「日本語版作成 → 英語翻訳 → 英語版のみ記号変換」になっている
- [ ] 日英で同じ論点・同じトーン（言語のみ差、読者別最適化なし）
- [ ] `## 日本語版` と `## English Version` で区切られている
- [ ] 各版がコードブロック（プレーン文・markdown装飾なし）で出力されている

## 絵文字

- [ ] 原則として絵文字を使っていない（【提案】タグもテキストのみ）
- [ ] 使う場合はパターンを統一している（見出しだけ・本文だけ等の混在なし）

## 状況フレーミング

- [ ] 人や過去を責めず、会社の事情・環境変化・状況変化に原因を帰属させている
- [ ] 「無駄」「非効率」「間違い」等の否定語を避けている

## 行数超過時

- [ ] 20行を超えた場合、背景説明 → リスク詳細 → 選択肢説明の順に削った
- [ ] 結論・コスト数字・推奨案・ベネフィットは残している
