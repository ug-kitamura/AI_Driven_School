# プレゼン原稿：openspec紹介（社内tech share・10〜15分）

## ① フック

出てきたものが、ちょっと違う。直してもらう。また違う。
何往復かして、ようやく「お、いいのが出た」となる。

これ、AIとコード書いてるときによくある感覚だと思うんですけど、まるで**AIガチャ**を回してるような感じ、ありませんか。
出力が安定しないので、地味に疲れるんですよね。

今日は、このガチャ運ゲーから抜け出す方法を持ってきました。**openspec**というツールの紹介です。

## ② 結論

一言で言うと、openspecは**仕様駆動開発**を支援するツールです。
AIとのやり取りを「仕様」として文書化して、その仕様をもとに実装させる。
今日はこれの、課題感、使い方、そして実際に使ってみて自分に何が起きたかを、15分でお話しします。

## ③ なぜ

さっきのガチャの話、もう少し掘ると、単に疲れるだけじゃなくて、もっと厄介な問題があります。

何往復もして、ようやく「これだ」というアウトプットにたどり着いても、そのやり取り自体はどこにも残らないんですよね。次に似たようなことをやるときには、また一からガチャを回すことになる。
しかも半年後とかに「あれ、なんでこの仕様にしたんだっけ」って、自分でも忘れてる。

つまり、AIとのやり取りの中に貴重な判断や試行錯誤が眠ってるのに、それを毎回捨てて、ゼロから始め直してるんです。これ、地味にもったいないと思うんですよ。

## ④ どうやって

openspecの考え方はシンプルです。AIとのやり取りを「仕様」として保存して、次のサイクルでその仕様を参照する。サイクルを回せば回すほど仕様が磨かれて、アウトプットの質が上がっていきます。

セットアップも軽いです。

1. 社内システムのNodeJS Selectorから、無料でNode.jsをインストール。v24系の最新を選ぶだけ。
2. `npm install -g @fission-ai/openspec@latest` を実行。
3. 作業フォルダで `openspec init`。環境選択でClaude Codeを選ぶと、`.claude/skills/` 以下にopenspecのスキルが入ります。

使い方は4つのスキルを順番に回すだけです。

1. **Explore** ─ planモードのようにアイデアを言語化する。まだファイルは作らない。
2. **Proposal** ─ 仕様を文書化して `openspec/changes/` に配置。なぜ・何を作るか、どう作るか、仕様、タスクの4点セットです。
3. **Apply** ─ 仕様をもとに実装。終わったタスクは記録されていく。
4. **Archive** ─ 完了した仕様を `openspec/archive/` に保存。ここに積み上がっていくのが、さっき言った「消えない資産」です。

正直に言うと、いいことばかりじゃありません。1サイクル回すのに、早くて30分、じっくりやると2時間以上かかることもあります。それに、慣れるまで仕組み自体がちょっと理解しづらい。クセはあります。
ただ、手戻りが減る分、トータルで見ると効率的というのが、使ってみての実感です。

## ⑤ どうなる

これを使い始めて、自分の中で一番変わったのはここです。

一度仕様を決めてしまえば、あとは実装するだけ。この状態がすごく楽なんです。
最近、正直あまりコードを書かなくなりました。じゃあ何をやってるかというと、仕様を詰めて、渡して、上がってきたものを見る。

感覚としては、**超絶優秀な部下を1人、マネジメントしている**ような感じなんですよね。
コードを書く人から、何を作るかを決める人に、自分の役割が変わった。ガチャを回す回数も、明らかに減りました。
