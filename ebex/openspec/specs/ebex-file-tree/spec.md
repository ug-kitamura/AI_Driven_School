## Requirements
### Requirement: 表示対象

Pane 1 は `workspace/` 直下の各プロジェクトフォルダと、その配下の **全階層** のサブフォルダ・ファイルを再帰ツリーとして表示しなければならない（SHALL）。`session.json` は Pane 1 に表示してはならない（MUST NOT）。⚠ サブフォルダ警告アイコンは表示してはならない（MUST NOT）。

#### Scenario: ネストしたフォルダとファイルが表示される

- **WHEN** `workspace/20260706-demo/sub/` に `deep.md` が存在する
- **THEN** Pane 1 に `20260706-demo` → `sub` → `deep.md` の階層が表示される

#### Scenario: session.json が非表示

- **WHEN** プロジェクトフォルダに `session.json` が存在する
- **THEN** Pane 1 のファイル一覧に `session.json` は表示されない

#### Scenario: サブフォルダ警告がない

- **WHEN** プロジェクトフォルダ内にサブフォルダが存在する
- **THEN** 警告アイコンは表示されずサブフォルダがツリーに表示される

### Requirement: Pane 1 ヘッダーロゴ

Pane 1 ヘッダーの「EBEX」テキスト左に `images/logo_small.png` を表示しなければならない（SHALL）。

#### Scenario: ロゴとタイトルが並ぶ

- **WHEN** ワークスペースが表示される
- **THEN** Pane 1 ヘッダーにロゴ画像と「EBEX」が左から順に表示される

### Requirement: 検索 UI

Pane 1 の検索行に下方向の区切り線（`border-b`）を表示してはならない（MUST NOT）。検索文字列が空でないとき、検索入力のクリアボタンが提供されなければならない（SHALL）。クリアボタンをクリックしても他の UI 要素の位置がずれてはならない（MUST NOT）。クリアボタンは短押し・長押しのいずれの操作でも確実に検索文字列を空にしなければならない（SHALL）。検索ボックスの右端は、Pane 1 ヘッダー右端の「フォルダ追加」ボタンの右端に揃えられなければならない（SHALL）。

#### Scenario: 検索下に横線がない

- **WHEN** ワークスペースが表示される
- **THEN** 検索バー直下に水平区切り線が存在しない

#### Scenario: 検索クリア

- **WHEN** ユーザーが検索ボックスに文字を入力する
- **THEN** クリアボタンが表示され、クリックで検索文字列が空になる

#### Scenario: クリアボタンの位置が安定している

- **WHEN** ユーザーが検索ボックスに文字を入力してからクリアボタンをクリックする
- **THEN** クリアボタンや検索入力の表示位置はクリック前後で変化しない

#### Scenario: 長押しでもクリアされる

- **WHEN** ユーザーがクリアボタンを長押しする
- **THEN** 検索文字列が空になる

#### Scenario: 検索ボックス幅がヘッダーボタンに揃う

- **WHEN** ワークスペースが表示される
- **THEN** 検索ボックスの右端は Pane 1 ヘッダーの「フォルダ追加」ボタンの右端と同じ横位置になる

### Requirement: 右クリックコンテキストメニュー

フォルダ行の右クリックメニュー項目は、表示順を **add folder → add file → rename → copy（該当時）→ paste（該当時）→ delete** とし、**delete は常に最後**でなければならない（SHALL）。プロジェクトフォルダ（`folderPath` に `/` を含まない）の場合は「add folder」「add file」「rename」「paste」「delete」としなければならない（SHALL）。サブフォルダ行の場合は「add folder」「add file」「rename」「copy」「paste」「delete」としなければならない（SHALL）。ファイル行のメニュー項目は「rename」「copy」「paste」「delete」としなければならない（SHALL）。`(no file)` 行のメニュー項目は「add folder」「add file」「paste」としなければならない（SHALL）。メニュー項目の表示言語は英語でなければならない（SHALL）。「add folder」「add file」「rename」「copy」「paste」の hover 背景色・文字色は、ツリー行の選択・強調時と同じグレー系トークンでなければならない（SHALL）。「delete」項目の hover 配色は destructive（赤系）のまま維持しなければならない（SHALL）。クリップボードが空のとき paste は無効（disabled）でなければならない（SHALL）。

#### Scenario: サブフォルダ行の右クリックメニュー

- **WHEN** ユーザーが `demo/sub` フォルダ行を右クリックする
- **THEN** add folder、add file、rename、copy、paste、delete の順で英語メニューが表示される

#### Scenario: プロジェクトフォルダ行の右クリックメニュー

- **WHEN** ユーザーが `demo` プロジェクトフォルダ行を右クリックする
- **THEN** add folder、add file、rename、paste、delete の順で英語メニューが表示され、copy は含まれない

#### Scenario: ネストファイルの右クリックメニュー

- **WHEN** ユーザーが `sub/deep.md` ファイル行を右クリックする
- **THEN** rename、copy、paste、delete の順で英語メニューが表示される

#### Scenario: 通常項目の hover はグレー

- **WHEN** ユーザーが右クリックメニューの rename 項目にマウスを重ねる
- **THEN** 背景色・文字色は青系ではなくグレー系トークンで表示される

#### Scenario: 削除項目の hover は赤系のまま

- **WHEN** ユーザーが右クリックメニューの delete 項目にマウスを重ねる
- **THEN** 背景色・文字色は destructive（赤系）で表示される

### Requirement: ツリー行の視覚フィードバック

ファイルが選択されているとき、当該ファイル行のテキストのみ太字（`font-semibold`）でなければならない（SHALL）。フォルダ行は、いかなる状態でも太字にしてはならない（MUST NOT）。フォルダ行はホバー時のみ背景色（`--workspace-tree-row` トークン、グレー系）を変化させ、選択時に背景色を変えてはならない（MUST NOT）。ファイル行はホバー時と選択時に同一の背景色（`--workspace-tree-row` トークン、グレー系）を用いなければならない（SHALL）。青系（`accent` 等）のトークンを行背景に用いてはならない（MUST NOT）。いずれの行背景色も、Pane 1 の通常時の背景色と同一であってはならない（MUST NOT）。選択中のファイル行にマウスオーバーしても、背景色は選択時と同じ濃さのままで変化してはならない（MUST NOT）。祖先フォルダ行を、選択中ファイルの強調のために背景色でハイライトしてはならない（MUST NOT）。

#### Scenario: ファイル選択時の太字

- **WHEN** ユーザーが `20260707-demo/sub/notes.md` を選択する
- **THEN** `notes.md` 行のみ太字で表示される

#### Scenario: フォルダ行は選択時に背景色が変わらない

- **WHEN** ユーザーが `20260707-demo/sub/notes.md` を選択する
- **THEN** `20260707-demo` 行と `sub` 行の背景色は通常時と同じであり、選択を示す背景色は付かない

#### Scenario: フォルダ行はホバー時のみ背景色が変わる

- **WHEN** ユーザーが選択されていないフォルダ行にマウスを重ねる
- **THEN** その行の背景色が `--workspace-tree-row` のグレー系で表示される

#### Scenario: ファイル行のホバーと選択の背景色が同一

- **WHEN** ユーザーがファイル行を選択する、または選択されていないファイル行にマウスを重ねる
- **THEN** 背景色はいずれも同一の `--workspace-tree-row` グレー系で表示される

#### Scenario: 選択中ファイル行のホバーで背景色が変わらない

- **WHEN** ユーザーが選択中のファイル行にマウスを重ねる
- **THEN** 背景色は選択時と同じ濃さのままであり、ホバーによって変化しない

### Requirement: フォルダ行の開閉と選択

フォルダツリーの展開・折りたたみは、フォルダ行左端の chevron ボタンのみで操作できなければならない（SHALL）。フォルダ名のクリックで展開・折りたたみを切り替えてはならない（MUST NOT）。フォルダ名のクリックで、現在選択中のファイル選択を変更してはならない（MUST NOT）。フォルダ名のクリックで、フォルダ内の先頭ファイルを自動選択してはならない（MUST NOT）。

#### Scenario: chevron で展開・折りたたみ

- **WHEN** ユーザーがフォルダ行の chevron ボタンをクリックする
- **THEN** 当該フォルダの子要素の表示が展開または折りたたみされる

#### Scenario: フォルダ名クリックでは開閉しない

- **WHEN** ユーザーが折りたたまれたフォルダ行のフォルダ名をクリックする
- **THEN** フォルダの展開状態は変化しない

#### Scenario: フォルダ名クリックではファイル選択を維持

- **WHEN** ユーザーが `20260707-demo/sub/notes.md` を選択した状態で、別のフォルダ名をクリックする
- **THEN** 選択中のファイルは `notes.md` のままであり、エディタの表示対象も変わらない

### Requirement: 検索フィルタ

Pane 1 上部に検索ボックスが提供されなければならない（SHALL）。キーワードにマッチするフォルダ名・ファイル名、またはそれらを含む祖先パスを持つノードのみが表示されなければならない（SHALL）。検索行の下に区切り線を表示してはならない（MUST NOT）。

#### Scenario: ネストファイル名でフィルタ

- **WHEN** ユーザーが検索ボックスに「deep」と入力する
- **THEN** `deep.md` を含むパスとその祖先フォルダのみが表示される

#### Scenario: フォルダ名でフィルタ

- **WHEN** ユーザーが検索ボックスに「sub」と入力する
- **THEN** 名前に `sub` を含むフォルダとその祖先・子孫のマッチが表示される

### Requirement: フォルダ追加

Pane 1 ヘッダー右上のフォルダ追加ボタンからモーダルが開かれなければならない（SHALL）。モーダルフッターには左からキャンセル・自動入力・確定の順でボタンが配置されなければならない（SHALL）。自動入力ボタンは入力欄に名前をセットするのみとし、モーダルを閉じてはならない（MUST NOT）。フォルダ作成は確定ボタンでのみ実行されなければならない（SHALL）。自動入力時の名前は `{YYYYMMDD}-untitled{N}` とし、N は同日の既存フォルダ名 `^{YYYYMMDD}-untitled(\d+)$` の最大値 + 1、存在しない場合は 1 としなければならない（SHALL）。

#### Scenario: 自動入力で名前がセットされる

- **WHEN** ユーザーがフォルダ追加モーダルで「自動入力」をクリックする
- **THEN** 入力欄に `20260707-untitled1` 形式の名前がセットされ、モーダルは開いたままである

#### Scenario: 通し番号のインクリメント

- **WHEN** `20260707-untitled1` と `20260707-untitled3` が既に存在し自動入力を実行する
- **THEN** 入力欄に `20260707-untitled4` がセットされる

#### Scenario: 確定でフォルダ作成

- **WHEN** ユーザーが自動入力後に「確定」をクリックする
- **THEN** 入力欄の名前で `workspace/` 配下にフォルダが作成される

### Requirement: フォルダリネーム

プロジェクトフォルダ（`workspace/` 直下、`folderPath` に `/` を含まない）の名前変更時のみ、モーダルフッターに「AI 自動入力」が表示されなければならない（SHALL）。サブフォルダの名前変更には AI 自動入力を表示してはならない（MUST NOT）。フォルダリネームダイアログの入力欄には、対象フォルダのパスから最終セグメント（フォルダ名）のみを表示しなければならない（SHALL）。確定時、システムは親パスと入力されたフォルダ名を結合して API の `toPath` を生成しなければならない（SHALL）。リネーム成功後、ツリー再読み込み（`onRefresh`）は選択状態の更新より先に完了しなければならない（SHALL）。

#### Scenario: サブフォルダリネームに AI 自動入力がない

- **WHEN** ユーザーが `20260707-demo/sub` の名前変更モーダルを開く
- **THEN** AI 自動入力ボタンは表示されない

#### Scenario: サブフォルダのリネーム入力はフォルダ名のみ

- **WHEN** ユーザーがパス `20260707-demo/sub` のフォルダをリネームし、入力欄に `sub-renamed` と入力して確定する
- **THEN** システムは API に `toPath: "20260707-demo/sub-renamed"` を送信する

### Requirement: フォルダ削除

プロジェクトフォルダ（`folderPath` に `/` を含まない）の削除は、直下に `session.json` 以外のファイルまたはサブフォルダが 1 つでも存在する場合はできてはならない（MUST NOT）。プロジェクトフォルダ直下に `session.json` のみが存在する場合は空フォルダとみなし、削除操作を実行できなければならない（SHALL）。サブフォルダ（`folderPath` に `/` を含む）の削除は、配下にファイルまたは子フォルダが存在する場合でも、警告ダイアログ表示後にユーザーが確認すれば再帰削除を実行できなければならない（SHALL）。サブフォルダの再帰削除は配下のすべてのファイルおよび子フォルダを含めて削除しなければならない（SHALL）。

#### Scenario: サブフォルダありプロジェクトフォルダは削除不可

- **WHEN** プロジェクトフォルダ内に空でないサブフォルダが存在する
- **THEN** 削除操作は無効またはエラーとなる

#### Scenario: session.json のみのプロジェクトフォルダは削除可能

- **WHEN** プロジェクトフォルダ直下に `session.json` のみが存在する
- **THEN** 削除操作が成功し、`session.json` を含めてフォルダが削除される

#### Scenario: 中身ありサブフォルダは警告後に削除可能

- **WHEN** ユーザーがファイルを含むサブフォルダ `demo/sub` の削除を実行し、警告ダイアログで確認する
- **THEN** `demo/sub` および配下のすべてのファイル・フォルダが削除される

### Requirement: ファイル操作

ファイルの追加は任意階層のフォルダ行のコンテキストメニュー add file から行えなければならない（SHALL）。DnD によるファイル追加は任意階層のフォルダ行、当該フォルダ内のファイル行、および OS からのフォルダ一括ドロップで行えなければならない（SHALL）。ペイン1 内 DnD によるファイル移動は同一プロジェクト内に限定されなければならない（SHALL）。

#### Scenario: サブフォルダへ DnD 追加

- **WHEN** ユーザーが外部ファイルを `sub` フォルダ行にドロップする
- **THEN** ファイルが `workspace/<project>/sub/` 配下に作成される

#### Scenario: ファイル行への DnD 追加

- **WHEN** ユーザーが外部ファイルを `sub/notes.md` ファイル行にドロップする
- **THEN** ファイルが `workspace/<project>/sub/` 配下に作成される

### Requirement: サブフォルダ追加

任意階層のフォルダ行のコンテキストメニュー「フォルダ追加」から、当該フォルダ直下にサブフォルダを作成できなければならない（SHALL）。モーダルにはキャンセルと確定が提供され、確定時のみ作成されなければならない（SHALL）。

#### Scenario: サブフォルダ作成

- **WHEN** ユーザーが `20260707-demo` 行の「フォルダ追加」で名前 `sub` を確定する
- **THEN** `workspace/20260707-demo/sub/` が作成されツリーに表示される

#### Scenario: ネストサブフォルダ作成

- **WHEN** ユーザーが `20260707-demo/sub` 行の「フォルダ追加」で名前 `inner` を確定する
- **THEN** `workspace/20260707-demo/sub/inner/` が作成される

### Requirement: ツリー階層の表示

ツリーの各階層には縦の階層線が表示されなければならない（SHALL）。同一階層のフォルダ/ファイルのテキスト開始位置は左揃えでなければならない（SHALL）。展開/折りたたみ用の chevron アイコンは既定サイズ（`size-4`）より小さいサイズで表示されなければならない（SHALL）。

#### Scenario: 階層縦線の表示

- **WHEN** `20260707-demo/sub/deep.md` が展開表示される
- **THEN** `sub` と `deep.md` の行に、親階層からの縦線が表示される

#### Scenario: テキスト左揃え

- **WHEN** 同じ階層にフォルダとファイルが存在する
- **THEN** フォルダ名とファイル名の文字開始位置は同じ横位置に揃う

### Requirement: スクロールバー

ツリー表示領域の縦スクロールバーは、Pane 2 / Pane 3 と同じ `workspace-scrollbar` クラスの見た目でなければならない（SHALL）。

#### Scenario: スクロールバーの見た目統一

- **WHEN** Pane 1 のツリーがスクロール可能な量のコンテンツを持つ
- **THEN** 表示されるスクロールバーは Pane 2 / Pane 3 のスクロールバーと同じ見た目になる

### Requirement: リネーム後の展開状態維持

フォルダのリネームが成功した場合、リネーム対象フォルダおよびその配下の展開状態（どのフォルダが開いているか）は、旧パスの状態を保持したまま新パスに引き継がれなければならない（SHALL）。旧パスに紐づく展開状態が新パスへの引き継ぎ後も別エントリとして残ってはならない（MUST NOT）。

#### Scenario: リネーム後に旧パスの表示が残らない

- **WHEN** ユーザーが展開済みのフォルダ `20260707-demo` を `20260707-renamed` にリネームする
- **THEN** `20260707-renamed` は展開済み状態を維持し、`20260707-demo` という旧パスに紐づく表示は残らない

#### Scenario: サブフォルダリネーム後の展開状態

- **WHEN** ユーザーが展開済みのサブフォルダ `20260707-demo/sub` を `20260707-demo/sub-renamed` にリネームする
- **THEN** `20260707-demo/sub-renamed` は展開済み状態を維持する

### Requirement: 追加・変更時の同名エラーはモーダル内に表示し、モーダルを閉じない

フォルダ追加・サブフォルダ追加・ファイル追加・フォルダリネーム・ファイルリネームの各ダイアログにおいて、確定した名前が既存の同階層のフォルダ／ファイルと同名になる場合、システムはエラーメッセージをダイアログ（モーダル）内に表示しなければならない（SHALL）。この場合、システムはダイアログを閉じてはならず（MUST NOT）、ペイン上部の共通エラー表示にはこのエラーを表示してはならない（MUST NOT）。

#### Scenario: 既存フォルダと同名のサブフォルダを追加しようとする

- **WHEN** ユーザーがフォルダ「シリーズA」にサブフォルダ追加を実行し、既に存在する子フォルダと同じ名前を入力して確定する
- **THEN** システムはダイアログ内にエラーメッセージを表示し、ダイアログは開いたままであり、フォルダ構成に変更を加えない

#### Scenario: 既存ファイルと同名のファイルにリネームしようとする

- **WHEN** ユーザーがファイルのリネームダイアログを開き、同じフォルダ内の別の既存ファイルと同じ名前を入力して確定する
- **THEN** システムはダイアログ内にエラーメッセージを表示し、ダイアログは開いたままであり、ファイル構成に変更を加えない

### Requirement: 名前未変更時のリネーム確定はモーダル内にエラーを表示し、モーダルを閉じない

リネームダイアログにおいて、入力された名前が変更前の名前と完全に一致する場合、システムは API を呼び出さず、エラーメッセージ「名前が変更されていません」をダイアログ（モーダル）内に表示しなければならない（SHALL）。この場合、システムはダイアログを閉じてはならず（MUST NOT）。ペイン上部の共通エラー表示にはこのエラーを表示してはならない（MUST NOT）。

#### Scenario: フォルダ名を変更せずに確定する

- **WHEN** ユーザーがフォルダのリネームダイアログを開き、名前を変更せずに確定を押す
- **THEN** システムはダイアログ内に「名前が変更されていません」と表示し、API リクエストは発行されず、ダイアログは開いたままであり、フォルダ構成に変更を加えない

#### Scenario: ファイル名を変更せずに確定する

- **WHEN** ユーザーがファイルのリネームダイアログを開き、名前を変更せずに確定を押す
- **THEN** システムはダイアログ内に「名前が変更されていません」と表示し、API リクエストは発行されず、ダイアログは開いたままであり、ファイル構成に変更を加えない

#### Scenario: 大文字小文字のみを変更した場合は通常のリネームとして扱われる

- **WHEN** ユーザーがフォルダ名の大文字小文字のみを変更して確定を押す（例: `Foo` → `foo`）
- **THEN** システムは名前変更ありとみなし、通常のリネーム処理を実行する

### Requirement: ファイル追加ダイアログのデフォルト入力値は空白である

フォルダの右クリックメニューから「ファイル追加」を実行した場合、名前入力欄の初期値は空白でなければならない（SHALL）。

#### Scenario: ファイル追加ダイアログを開く

- **WHEN** ユーザーがフォルダを右クリックし「ファイル追加」を選択する
- **THEN** 名前入力欄は空白であり、`notes.md` 等のデフォルト値は入っていない

### Requirement: モーダルは Enter キーで確定できる

フォルダ・ファイルの追加・リネーム用ダイアログにおいて、名前入力フィールドでの Enter キー押下は、確定ボタンのクリックと同じ動作を実行しなければならない（SHALL）。確定ボタンが無効化されている条件（未入力・処理中など）では、Enter キー押下も同様に確定を実行してはならない（MUST NOT）。

#### Scenario: 入力後に Enter キーで確定する

- **WHEN** ユーザーがフォルダ追加ダイアログの名前入力欄に有効な名前を入力し、Enter キーを押す
- **THEN** システムは確定ボタンを押した場合と同じ処理（フォルダ作成）を実行する

#### Scenario: 未入力状態で Enter キーを押しても確定しない

- **WHEN** ユーザーが名前入力欄を空のままで Enter キーを押す
- **THEN** システムは何も作成・変更せず、ダイアログは開いたままである

### Requirement: ファイル一覧に拡張子カテゴリに応じたアイコンを表示する

ファイルツリーの各ファイル行には、ファイル名から判定したカテゴリ（テキスト、コード、表、画像、動画、音声、シークレット/設定、zip、その他）に対応する控えめな lucide-react アイコンを表示しなければならない（SHALL）。カテゴリ判定は拡張子（大文字小文字を区別しない）に基づくが、`.env` や `.env.local` のように拡張子を持たない、または拡張子だけでは判別できないファイル名は、ファイル名そのものとの一致で判定しなければならない（SHALL）。テキストカテゴリには `.md`、`.txt`、`.html`、`.htm` を含めなければならない（SHALL）。コードカテゴリには `.yaml`、`.tsx`、`.jsx`、`.groovy`、`.bat`、`.sh`、`.json`、`.yml`、`.xml` を含めなければならない（SHALL）。画像カテゴリには `.jpeg`、`.svg` を含めなければならない（SHALL）。シークレット/設定カテゴリには `.crt` および `.env`、`.env.*` パターン（例: `.env.local`、`.env.template`、`.env.example`）を含めなければならない（SHALL）。その他カテゴリには `.pptx` を含めなければならない（SHALL）。`.gif` は動画カテゴリ、`.vtt` は音声カテゴリとして扱わなければならない（SHALL）。各カテゴリのアイコンは、視認性を保ちつつ主張しすぎない薄いトーンの色を持たなければならない（SHALL）。用途が近いカテゴリ（テキスト/コード/表、画像/動画/音声）は同じ色調を共有してよい（MAY）が、その場合もアイコンの形状でカテゴリを区別できなければならない（SHALL）。

#### Scenario: Markdown ファイルにテキストアイコンが表示される

- **WHEN** フォルダ内に `notes.md` が存在する
- **THEN** ファイル一覧の該当行の左側に、テキストカテゴリのアイコンが控えめな色で表示される

#### Scenario: HTML ファイルにテキストアイコンが表示される

- **THEN** ファイル一覧の該当行の左側に、テキストカテゴリ（`FileText`）のアイコンが表示される

#### Scenario: 拡張子不明のファイルには汎用アイコンが表示される

- **THEN** ファイル一覧の該当行の左側に、その他カテゴリの汎用ファイルアイコンが表示される

#### Scenario: env 系の派生ファイル名もシークレットカテゴリになる

- **WHEN** フォルダ内に `.env.local` が存在する
- **THEN** ファイル一覧の該当行の左側に、シークレット/設定カテゴリのアイコンが表示される

#### Scenario: gif は動画カテゴリとして扱われる

- **WHEN** フォルダ内に `.gif` ファイルが存在する
- **THEN** ファイル一覧の該当行の左側に、動画カテゴリのアイコンが表示される

### Requirement: フォルダツリーはフォルダを先にファイルを後に表示する

フォルダツリーの各階層において、システムはサブフォルダをファイルより前に表示しなければならない（SHALL）。

#### Scenario: フォルダとファイルが混在する階層の表示順

- **WHEN** あるフォルダの直下にサブフォルダとファイルが両方存在する
- **THEN** システムはすべてのサブフォルダをファイルより上に表示する

### Requirement: DnD エラーはペイン上部に表示する

ドラッグ&ドロップによるファイル追加が失敗した場合、システムはエラーメッセージを Pane 1 上部の共通エラー表示に示さなければならない（SHALL）。このエラーを追加・リネーム用モーダル内に表示してはならない（MUST NOT）。

#### Scenario: DnD 失敗時の表示位置

- **THEN** エラーメッセージは Pane 1 上部に表示され、モーダルは開かない

### Requirement: キーボードによるツリーナビゲーション

Pane 1 のツリーは、キーボードによるカーソル位置移動と開閉操作をサポートしなければならない（SHALL）。↑ / ↓ キーはカーソル位置を移動し、移動先の行をカーソル位置とし、当該行が表示領域内に入るようスクロールしなければならない（SHALL）。カーソル移動は Pane 2 の表示対象（選択中ファイル）を変更してはならない（MUST NOT）。Enter キーは、カーソルがフォルダ行にあるとき展開/折りたたみを切り替え、ファイル行にあるとき当該ファイルを Pane 2 で開かなければならない（SHALL）。Enter または chevron によるフォルダ開閉後、カーソル位置は当該フォルダ行のままでなければならない（SHALL）。→ キーは、カーソルが折りたたみ中のフォルダ行にあるときのみ当該フォルダを展開しなければならない（SHALL）。展開済みフォルダまたはファイル行で → を押しても Pane 2 を変更してはならない（MUST NOT）。← キーおよび Backspace キーは次のとおりでなければならない（SHALL）: **(a)** カーソルが展開中のフォルダ行（プロジェクトフォルダ・サブフォルダを問わない）にあるとき、当該フォルダを折りたたみ、カーソル位置は当該フォルダ行のままとする。**(b)** カーソルが折りたたみ済みのサブフォルダ行にあるとき、カーソル位置を親フォルダ行へ移動する（折りたたみ状態は変えない）。**(c)** カーソルが折りたたみ済みのプロジェクトフォルダ行にあるとき、何もしない。**(d)** カーソルがファイル行にあるとき、当該ファイルの親フォルダを折りたたみ、カーソル位置は折りたたまれた親フォルダ行とする。検索入力にフォーカスがある間、またはモーダルが開いている間はツリーのキーボード操作を処理してはならない（MUST NOT）。

#### Scenario: 上下キーでカーソル移動し Pane 2 は維持

- **WHEN** ユーザーが `notes.md` を Pane 2 で開いた状態で、別の行へ ↑ または ↓ でカーソルを移動する
- **THEN** カーソル行のみ背景色が変化し、Pane 2 は `notes.md` のまま表示される

#### Scenario: 上下キーで移動先がスクロール表示される

- **WHEN** ユーザーが ↑ / ↓ で表示領域外の行へカーソルを移動する
- **THEN** カーソル位置の行がツリー表示領域内にスクロール表示される

#### Scenario: Enter でフォルダを展開しカーソルは維持

- **WHEN** ユーザーが折りたたまれたフォルダ行にカーソルがあり Enter を押す
- **THEN** 当該フォルダが展開され、カーソル位置は当該フォルダ行のままであり、Pane 2 の表示は変化しない

#### Scenario: Enter でファイルを開く

- **WHEN** ユーザーがファイル行にカーソルがあり Enter を押す
- **THEN** Pane 2 で当該ファイルが開かれる

#### Scenario: 展開中サブフォルダを Backspace で折りたたむ

- **WHEN** ユーザーが展開中の `demo/sub` フォルダ行にカーソルがあり Backspace を押す
- **THEN** `sub` フォルダが折りたたまれ、カーソル位置は `sub` 行のままである

#### Scenario: 展開中プロジェクトフォルダを Backspace で折りたたむ

- **WHEN** ユーザーが展開中の `demo` プロジェクトフォルダ行にカーソルがあり Backspace を押す
- **THEN** `demo` フォルダが折りたたまれ、カーソル位置は `demo` 行のままである

#### Scenario: 折りたたみ済みサブフォルダで Backspace すると親へ移動

- **WHEN** ユーザーが折りたたみ済みの `demo/sub` 行にカーソルがあり Backspace を押す
- **THEN** カーソル位置は `demo` 行へ移動する

#### Scenario: ファイル行で Backspace すると親フォルダが閉じる

- **WHEN** ユーザーが `demo/sub/notes.md` 行にカーソルがあり Backspace を押す
- **THEN** `sub` フォルダが折りたたまれ、カーソル位置は `sub` 行となる

### Requirement: キーボードショートカット

ツリー表示領域にフォーカスがあるとき、システムは Ctrl+C（copy）、Ctrl+V（paste）、Delete（delete）、F2（rename）を処理しなければならない（SHALL）。検索入力またはモーダルにフォーカスがある間はこれらのショートカットをツリー操作として処理してはならない（MUST NOT）。Ctrl+C はサブフォルダ行およびファイル行でのみ有効でなければならない（SHALL）。Ctrl+V はプロジェクトフォルダ行、サブフォルダ行、ファイル行、`(no file)` 行で有効でなければならない（SHALL）。ファイル行での Ctrl+V は、当該ファイルの親フォルダへ paste しなければならない（SHALL）。クリップボードが空のとき paste（メニューおよび Ctrl+V）は無効でなければならない（SHALL）。

#### Scenario: Ctrl+C でサブフォルダをコピー

- **WHEN** ユーザーがサブフォルダ行にカーソルがあり Ctrl+C を押す
- **THEN** 当該フォルダがクリップボードに保存される

#### Scenario: Ctrl+V でプロジェクトフォルダへ貼り付け

- **WHEN** ユーザーがファイルをコピーした後、プロジェクトフォルダ行にカーソルがあり Ctrl+V を押す
- **THEN** 当該プロジェクトフォルダ直下にファイルが複製される

#### Scenario: Ctrl+V でファイル行から親フォルダへ貼り付け

- **WHEN** ユーザーがファイルをコピーした後、`demo/sub/notes.md` ファイル行にカーソルがあり Ctrl+V を押す
- **THEN** `demo/sub/` 配下にファイルが複製される

#### Scenario: F2 でリネームダイアログを開く

- **WHEN** ユーザーがファイル行にカーソルがあり F2 を押す
- **THEN** 当該ファイルのリネームダイアログが開く

#### Scenario: Delete で削除確認

- **WHEN** ユーザーがファイル行にカーソルがあり Delete を押す
- **THEN** 当該ファイルの削除確認ダイアログが開く

### Requirement: 空フォルダのプレースホルダ表示

展開済みで子フォルダおよびファイルがともに存在しないフォルダに対し、システムはアイコンなしの `(no file)` テキストを `text-muted-foreground` で表示しなければならない（SHALL）。`(no file)` 行の右クリックメニューは add folder、add file、paste を提供しなければならない（SHALL）。`(no file)` 行に copy を表示してはならない（MUST NOT）。

#### Scenario: 空フォルダ展開時にプレースホルダ表示

- **WHEN** ユーザーが空のサブフォルダ `demo/empty` を展開する
- **THEN** 子要素として `(no file)` が薄いグレーテキストで表示される

#### Scenario: no file 行からファイル追加

- **WHEN** ユーザーが `(no file)` 行を右クリックし add file を選択する
- **THEN** 親フォルダへのファイル追加ダイアログが開く

### Requirement: 右クリック中の行ハイライト維持

右クリックでコンテキストメニューを開いた行は、マウスがメニュー上に移動しても、メニューが閉じるまで `--workspace-tree-row` 背景色を維持しなければならない（SHALL）。CSS `:hover` のみに依存してはならない（MUST NOT）。

#### Scenario: メニュー操作中も背景維持

- **THEN** 右クリックしたファイル行の背景色はメニューが閉じるまで維持される

### Requirement: ペイン1 内ドラッグ&ドロップ（移動）

サブフォルダ行およびファイル行は、ペイン1 内でのドラッグ&ドロップによる移動のソースとなれなければならない（SHALL）。プロジェクトフォルダ行（`folderPath` に `/` を含まない）はドラッグソースとしてはなってはならない（MUST NOT）。ドロップ先は任意のフォルダ（プロジェクトフォルダ・サブフォルダを含む）でなければならない（SHALL）。ファイル行へのドロップは当該ファイルの親フォルダへの移動として扱わなければならない（SHALL）。移動元と移動先が異なるプロジェクトフォルダに属する場合、システムは移動を拒否しエラーを表示しなければならない（SHALL）。フォルダを自身の子孫フォルダへドロップしてはならない（MUST NOT）。同名のファイルまたはフォルダが移動先に存在する場合、システムは「paste/DnD 時の同名自動リネーム」要件に従い `-{通し番号}` 付きの一意名で移動しなければならない（SHALL）。

#### Scenario: サブフォルダを同一プロジェクト内で移動

- **WHEN** ユーザーが `demo/sub-a` を `demo/sub-b` 内へドラッグ&ドロップする
- **THEN** `demo/sub-b/sub-a` として移動される

#### Scenario: プロジェクトまたぎ移動は拒否

- **WHEN** ユーザーが `demo-a/sub/file.md` を `demo-b` へドラッグ&ドロップする
- **THEN** 移動は実行されず、Pane 1 のエラーメッセージボックスにエラーが表示される

#### Scenario: ファイル行へのドロップは親フォルダへ

- **WHEN** ユーザーが `other.md` を `demo/notes.md` 行へドロップする
- **THEN** `other.md` は `demo/` 配下に移動される

#### Scenario: 移動先に同名ファイルがある場合は自動リネーム

- **WHEN** ユーザーが `notes.md` を `demo/` 内の別ファイル行へドロップし、`demo/notes.md` が既に存在する
- **THEN** 移動後のファイル名は `notes-2.md` となる

### Requirement: OS からのフォルダ一括ドラッグ&ドロップ

OS（エクスプローラー等）から複数のフォルダおよびファイルをドロップした場合、システムはフォルダ構造を保持したままドロップ先フォルダ配下に追加しなければならない（SHALL）。同名衝突時は「paste/DnD 時の同名自動リネーム」要件に従い `-{通し番号}` 付きの一意名で追加しなければならない（SHALL）。

#### Scenario: ネストフォルダを OS から追加

- **WHEN** ユーザーが `folder-x/sub/a.md` 構造を持つフォルダを `demo` へドロップする
- **THEN** `demo/folder-x/sub/a.md` が作成される

#### Scenario: OS DnD で同名ファイルがある場合は自動リネーム

- **WHEN** ユーザーが `report.md` を `demo` へドロップし、`demo/report.md` が既に存在する
- **THEN** `demo/report-2.md` が作成される

### Requirement: ドロップ先の視覚的フィードバック

ドラッグ中、システムは現在のドロップ先フォルダを枠線で囲んで表示しなければならない（SHALL）。フォルダ行またはその配下のファイル行上にカーソルがある場合、当該フォルダ全体（フォルダ行と展開済み子領域）を枠で囲まなければならない（SHALL）。サブフォルダ行上にカーソルがある場合、当該サブフォルダのみを枠で囲み、親フォルダの枠は表示してはならない（MUST NOT）。枠線は行背景の `--workspace-tree-row` とは異なる視覚（例: `ring-primary`）でなければならない（SHALL）。

#### Scenario: ファイル行ホバー時に親フォルダ全体が枠表示

- **WHEN** ユーザーが `demo` 配下の `notes.md` 行の上でファイルをドラッグする
- **THEN** `demo` フォルダ全体が枠で囲まれる

#### Scenario: サブフォルダ上ではサブフォルダのみ枠表示

- **WHEN** ユーザーが `demo/sub` 行の上でファイルをドラッグする
- **THEN** `sub` フォルダのみが枠で囲まれ、親 `demo` 全体の枠は表示されない

### Requirement: copy と paste

システムはファイルおよびサブフォルダの copy と paste を提供しなければならない（SHALL）。copy は右クリックメニューおよび Ctrl+C で実行できなければならない（SHALL）。paste は右クリックメニューおよび Ctrl+V で実行できなければならない（SHALL）。プロジェクトフォルダ行の右クリックメニューに copy を含めてはならない（MUST NOT）。プロジェクトフォルダ行の右クリックメニューおよび Ctrl+V には paste を含めなければならない（SHALL）。サブフォルダ行のメニューには copy と paste を含めなければならない（SHALL）。ファイル行のメニューには copy と paste を含めなければならない（SHALL）。paste 先は、フォルダ行（プロジェクト・サブフォルダ）では当該フォルダ直下、ファイル行では当該ファイルの親フォルダ、`(no file)` 行ではその親フォルダでなければならない（SHALL）。copy/paste はプロジェクトフォルダをまたいで実行できなければならない（SHALL）。paste 先に同名のファイルまたはフォルダが存在する場合、システムは「paste/DnD 時の同名自動リネーム」要件に従い `-{通し番号}` 付きの一意名で複製しなければならない（SHALL）。

#### Scenario: サブフォルダを別プロジェクトへコピー

- **WHEN** ユーザーが `demo-a/sub` を copy し、`demo-b` で paste する
- **THEN** `demo-b/sub` が作成され、`demo-a/sub` は残る

#### Scenario: 同名ファイルを paste すると自動リネーム

- **WHEN** ユーザーが `notes.md` を copy し、既に `notes.md` が存在するフォルダへ paste する
- **THEN** `notes-2.md` が作成される

#### Scenario: ファイル行から paste すると親フォルダへ複製

- **WHEN** ユーザーが `readme.md` を copy し、`demo/sub/notes.md` ファイル行で paste する
- **THEN** `demo/sub/readme.md` または同名衝突時は `demo/sub/readme-2.md` 等が作成される

### Requirement: Pane 1 共通エラーのメッセージボックス表示

Pane 1 の共通エラー（DnD 失敗、copy/paste 失敗、移動拒否等。モーダル内エラーは対象外）は、検索バーとツリー表示領域の間にメッセージボックスとして表示されなければならない（SHALL）。メッセージボックスは角丸（`rounded-lg`）のコンパクトな枠とし、帯状にペイン全幅へ横断してはならない（MUST NOT）。背景は `bg-destructive/10`、枠線は `border-destructive/20` 等の destructive 系トークンで視認性を確保しなければならない（SHALL）。左に警告アイコン（`AlertCircle`、`text-destructive`）、中央にエラーメッセージ（`text-sm text-destructive`）、右に dismiss 用の ✕ ボタンを配置しなければならない（SHALL）。✕ ボタンのアイコン色は警告アイコンと同じ `text-destructive` でなければならない（SHALL）。✕ ボタンはメッセージボックス内で警告アイコンおよびテキストと**垂直方向に中央揃え**でなければならない（SHALL）。✕ ボタンのクリックでエラー表示を消去できなければならない（SHALL）。ユーザーが Pane 1 上で別の操作（行クリック、キーボード操作、ファイル選択、フォルダ開閉、ダイアログを開く、検索文字列変更、copy/paste/delete 操作開始、DnD 開始等）を開始した場合、表示中のエラーは消去されなければならない（SHALL）。マウスホバーのみではエラーを消去してはならない（MUST NOT）。新しいエラーが発生した場合は直前のエラーを置き換えなければならない（SHALL）。タイマーによる自動消去を設けてはならない（MUST NOT）。

#### Scenario: エラーがメッセージボックスで表示される

- **WHEN** ユーザーが DnD 操作を実行し失敗する
- **THEN** 検索バーとツリーの間に角丸のメッセージボックスが表示され、警告アイコンとエラーメッセージが含まれる

#### Scenario: ✕ ボタンで消去

- **WHEN** ユーザーがエラーメッセージボックスの ✕ ボタンをクリックする
- **THEN** メッセージボックスが消える

#### Scenario: 別操作開始でエラーが消える

- **WHEN** エラーメッセージが表示されている状態で、ユーザーが別のファイル行をクリックする
- **THEN** メッセージボックスが消える

#### Scenario: ホバーだけではエラーが消えない

- **WHEN** エラーメッセージが表示されている状態で、ユーザーが別行にマウスを移動する（クリックしない）
- **THEN** メッセージボックスは表示されたままである

#### Scenario: 新しいエラーで置き換え

- **WHEN** エラー A が表示されている状態で、別の操作がエラー B を発生させる
- **THEN** メッセージボックスの内容はエラー B に置き換わる

#### Scenario: モーダル内エラーは対象外

- **WHEN** ユーザーがリネームダイアログで同名エラーを発生させる
- **THEN** エラーはダイアログ内にのみ表示され、Pane 1 のメッセージボックスは表示されない

### Requirement: ツリーカーソル位置

Pane 1 のツリーは、キーボード操作およびクリックによって移動する**カーソル位置**（現在行）を 1 行のみ保持しなければならない（SHALL）。カーソル位置は `--workspace-tree-row` 背景色で表示しなければならない（SHALL）。マウスホバーはカーソル位置を変更してはならない（MUST NOT）。ホバー時の背景色は CSS `:hover` による一時表示とし、カーソル位置の状態とは独立でなければならない（SHALL）。Pane 2 のファイル選択（太字表示）とカーソル位置は別概念であり、カーソル移動だけでは Pane 2 を変更してはならない（MUST NOT）。カーソル位置の表示に DOM focus ring（青系 `ring` / `outline`）を用いてはならない（MUST NOT）。

#### Scenario: ホバーだけではカーソルが動かない

- **WHEN** ユーザーがキーボードで `git-series-spec.md` 行をカーソル位置とした後、マウスを `notes.md` 行へ移動する（クリックしない）
- **THEN** `git-series-spec.md` 行がカーソル位置（背景色）のままであり、`notes.md` 行はホバー表示のみとなる

#### Scenario: クリックでカーソルが移動する

- **WHEN** ユーザーが `notes.md` 行をクリックする
- **THEN** `notes.md` 行がカーソル位置となり、背景色が移動する

#### Scenario: カーソル表示に青枠がない

- **WHEN** ユーザーが ↑ / ↓ またはクリックでツリー行のカーソル位置を移動する
- **THEN** カーソル位置はグレー背景のみで示され、行またはツリー領域に青系 focus ring は表示されない

### Requirement: paste/DnD 時の同名自動リネーム

paste および DnD（ペイン1 内移動、OS からのファイル/フォルダ追加）において、配置先に同名のファイルまたはフォルダが存在する場合、システムはエラーで停止せず、名前の末尾に `-{通し番号}` を付与した一意名で作成または移動しなければならない（SHALL）。ファイルの場合、拡張子の直前に `-{通し番号}` を挿入しなければならない（SHALL）（例: `test.md` → `test-2.md`）。フォルダの場合、フォルダ名末尾に `-{通し番号}` を付与しなければならない（SHALL）（例: `folder` → `folder-2`）。通し番号は、同一配置先における `{基底名}-{N}` パターン（ファイルは拡張子除く基底名）の **最大 N に 1 を加えた値** とし、N は 2 から開始しなければならない（SHALL）。`test.md` のみ存在する場合の最初の衝突名は `test-2.md` でなければならない（SHALL）。ダイアログ経由の追加・リネームにおける同名エラーは従来どおりモーダル内エラーとし、本自動リネームの対象外でなければならない（MUST NOT）。

#### Scenario: 同名ファイルを paste すると -2 が付く

- **WHEN** ユーザーが `test.md` を copy し、既に `test.md` が存在するフォルダへ paste する
- **THEN** `test-2.md` が作成される

#### Scenario: -2 存在時は -3 が付く

- **WHEN** 配置先に `test.md` と `test-2.md` が存在し、ユーザーが `test.md` を paste する
- **THEN** `test-3.md` が作成される

#### Scenario: DnD 同名衝突も自動リネーム

- **WHEN** ユーザーが外部から `report.md` をドロップし、配置先に既に `report.md` が存在する
- **THEN** `report-2.md` として作成される

#### Scenario: ダイアログ追加の同名は従来どおりエラー

- **WHEN** ユーザーが add file ダイアログで既存ファイルと同名を入力して確定する
- **THEN** モーダル内にエラーが表示され、自動リネームは行われない
