# 材料の集め方

提案文書に使う事実を、対話で集めるための指針。

表現のルールは [writing-essence.md](writing-essence.md)、対話の進め方と構成は [SKILL.md](../SKILL.md) が扱う。ここは材料だけを扱う。

## 提案文書に要る事実

書く前に全部の軸を通す。ただし全部を聞くのではない。読み手がその問いを持たないと判断した軸は、聞かずに落とす。すでに分かっているものも聞かない。

| 軸 | 押さえるもの |
|---|---|
| 規模 | 何人 / どれくらいの量 / いくら |
| 期間 | いつから / いつまで / どれくらい続くか |
| 判定 | 終わったとき、何をもって成功とするか<br>何が起きたら失敗と判断して撤退するか |
| 次の一手 | 通ったら、誰が何をするか<br>・提案相手 — 承認のほかに、することはあるか<br>・提案者 — まず何から始めるか<br>・対象者 — 何をしてもらうことになるか |
| 影響 | 誰が困るか / 何が止まるか / 何をやめることになるか |
| 出所 | その数字はどこから来たか（実測 / 推定 / 伝聞） |

**これは点検する視点であって、質問リストではない。** 上から順に読み上げない。提案の種類ごとに1行を選ぶ分類表としても使わない。全部の軸が毎回同時に効く。

軸を落とす基準は「読み手がその問いを持たないとき」。読み手の頭に浮かぶ問いなら必ず聞く。

軸の意図：

- **判定に撤退条件を含める** — やめ方が決まっている提案のほうが承認されやすい
- **次の一手を3者に分ける** — 主語の混ざった段取り（「今週中にご都合を伺えれば、来月の枠を確保できます」）を書けなくする
- **出所を押さえる** — 実測と推定を区別しないまま数字を置かない

## ぼかしの検出

**ぼかしは、知らないことの跡。**

「数名」「希望者」「早めに」「一定の効果」「継続的に」——こうした語を書きそうになったら、それは事実が手元にないサイン。ぼかさずにユーザーに聞く。

軸の表とぼかしの検出は、守備範囲が違う。両方いる。

| | 効くタイミング | 見つかるもの |
|---|---|---|
| 軸の表 | 書く前 | 書かなかった項目 |
| ぼかしの検出 | 書きながら | ぼかして書けてしまった項目 |

## 事実が手元にないとき

聞く。返ってきた答えで進み方を変える。

| ユーザーの答え | 扱い |
|---|---|
| 答えが返った | そのまま使う |
| 答えられない | 一緒に見積もり、合意してから使う |
| 見積もりようがない | その話題に触れない。ぼかして書かない |

これを、手元にない事実がなくなるまで繰り返す。

## フェルミ推定

数字が出てこないときは、ユーザーと一緒に見積もる。AIが単独で置かない。

1. 推定が可能になるところまで、材料をユーザーから引き出す
2. 算出した結果をユーザーに示し、違和感がないか聞く
3. 違和感があれば理由を聞き、計算に足りない材料を引き出して計算し直す
4. ユーザーが納得するまで 2〜3 を繰り返す

合意した推定は、計算の根拠を本文に残す。「1件30分 × 週10件 ＝ 月20時間」のように書けば、読み手が自分で検算できる。

## 根拠の強さ

```
強 ┃ 数字・データ ＞ 専門家の意見 ＞ 体験談 ＞ たとえ話 ＞ 思い込み ┃ 弱
```

ただし現実の意思決定は感情で動く。**ベストは「数字＋心を動かす話（体験談など）」**。強い数字が出せないときは、体験談や具体的なエピソードで代替してよい。

絵を浮かばせる材料にも強さの順番がある：**①実際に見た場面（最強・AIには作れない）→ ②読み手に身近なたとえ → ③数字・データ（土台として必須だが、それだけでは絵にならない）**。まず①を探し、なければ②で補い、③で支える。

## 材料⑤の掘り方

合意したストーリーレベルの箇所数だけ掘る。Lv0 なら掘らない。

1. **超具体的にする** — 場面をスローモーションで見る。「いつ・どこで」「周りに誰がいて、どんな顔だったか」
2. **心の声を入れる** — 「その時、心の中で何と言っていましたか？」
3. **たとえる** — 読み手が知らないことは、知っていることに乗せる。**たとえはAIが案を出してよい**（体験の創作は禁止だが、誰もが知る場面へのたとえはAIの得意技）。複数案を出し、読み手にいちばん近いものをユーザーに選んでもらう

**1回で出なくても諦めない。** 角度を変えて2〜3回試す（回数は目安であって固定ではない）。合意したレベルの箇所数が埋まらなければ、埋まった分だけで書く。場面を作り出してはならない。

あわせて次の2つも会話の流れで拾う。独立した質問項目にはしない。

- **弱さ** — 「正直、最初は半信半疑でした」のような、つまずいた瞬間や正直な気持ち。ひと言でいい。堅い場では無理に出さない
- **懸念の先出し** — 読み手の頭に浮かぶ突っ込みどころと、その答え。気づかれる前にこちらから出すと通りやすい

## 絵の置き場

絵は理由・具体の側に置く。Lv2 以上でも、山場の絵は1つに絞る。全部を山にすると、全部が平らになる。

## 対話の流れ（例）

ユーザーが雑に投げ、AIが1問ずつ推奨案つきで材料を引き出す。特に③相手の問いは答えにくいので、質問するだけでなく推奨案を示す。

> ユーザー：定例会議を減らしたい
> AI：Q1（あと4〜5問ほど）：①は「定例会議を減らす」ですね。②決めるのは誰ですか？ チームの定例なら直属の部長が承認者になりがちです。これでいいですか？
> ユーザー：部長です
> AI：Q2（あと3〜4問ほど）：ストーリーはどのくらい入れますか？ 部長宛の社内提案なら Lv1（見た場面を1箇所だけ）がおすすめです。
> ユーザー：それで
> AI：Q3（あと2〜3問ほど）：③部長の頭の中の問いは「どの会議か／何がよくなるか／自分は何をすればいいか」が刺さります。この3つに答える形でOKですか？
> ユーザー：OK
> AI：Q4（あと2問ほど）：③に答えるなら、冒頭で削減時間を数字で出すのがおすすめです。④根拠になる数字はありますか？
> ユーザー：週7本・12時間、直近は7人中2人しか発言していない
> AI：Q5（あと1問ほど）：減らした後は何本・何時間になりますか？ 見当がつかなければ一緒に見積もります。
> ユーザー：3本減らして週9時間
> AI：Q6（あと1問ほど）：⑤その会議で「これは要らない」と思った場面はありますか？
