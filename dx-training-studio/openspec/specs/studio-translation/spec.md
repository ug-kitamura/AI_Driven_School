# studio-translation Specification

## Purpose

Studio の翻訳編集（日本語正本 → 英語派生）の正本。編集言語の状態・言語切替と鮮度チップの設置場所・英語ビューの構成・翻訳 API（stateless / Sonnet 5 固定 / 契約注入）・en 本文の読み書き・「最新として扱う」を定める。

## Requirements

### Requirement: 編集言語は Workspace が持つ1つの状態である

Studio の編集言語（`ja` / `en`）はワークスペースの単一の状態としなければならない（SHALL）。レッスン選択時は本文エディタと鉛筆ダイアログの中身が同じ状態に連動しなければならない（SHALL）——本文とメタで別々の言語にはできない。選択階層が変わったとき、編集言語は `ja` に戻さなければならない（SHALL）。切替時に未保存の入力があれば破棄する（既存メタビューの作法に従う）。

#### Scenario: レッスンの本文とメタが連動する

- **WHEN** レッスン選択中に言語切替で英語モードにする
- **THEN** ペイン3 のエディタは `contents.en.md` の内容になり、鉛筆ダイアログは英語フィールドの編集になる

#### Scenario: 選択が変わると日本語へ戻る

- **WHEN** 英語モードのまま別のレッスンを選択する
- **THEN** 編集言語は `ja` に戻っている

### Requirement: 言語切替と鮮度チップは4か所のヘッダーに置く

言語切替（lucide `languages` アイコン）と鮮度チップは、次の4か所のヘッダーにのみ置かなければならない（SHALL）: ①ホームビュー ②シリーズメタビュー ③コースメタビュー ④レッスン表示時のペイン2 ヘッダー（鉛筆ボタンの横）。チップはビューの中ではなく切替の横に常駐し、日英どちらのビューでも見えなければならない（SHALL）。ツリーの行には翻訳状態を表示してはならない（SHALL NOT）。

チップの表示は「未翻訳」「英語版が古い」の2種とし、最新のときは何も表示しない（SHALL NOT）。レッスンのチップは本文とメタの判定の悪いほうを表示しなければならない（SHALL）。判定規則は `translation-freshness` capability に従う。

#### Scenario: 未翻訳のチップ

- **WHEN** `contents.en.md` も `_en` フィールドも無いレッスンを選択する
- **THEN** ペイン2 ヘッダーに「未翻訳」チップが表示される

#### Scenario: 本文だけ古いレッスンのチップ

- **WHEN** メタの翻訳は最新だが本文の原文ハッシュが一致しないレッスンを選択する
- **THEN** チップは「英語版が古い」を表示する

#### Scenario: 最新ならチップが出ない

- **WHEN** 本文・メタとも翻訳が最新のレッスンを選択する
- **THEN** チップは表示されない

### Requirement: 英語ビューは翻訳対象フィールドだけを原文併記で編集する

英語ビューには翻訳対象フィールドだけを表示しなければならない（SHALL）: 全体=`name_en` / `description_en`、シリーズ=`name_en` / `catch_en` / `description_en`、コース=`name_en` / `catch_en` / `description_en` / `target_en`、レッスン（鉛筆ダイアログ）=`name_en` / `description_en` / `author_en`。各入力には対応する日本語原文（名前はフォルダ名）を読取専用で併記しなければならない（SHALL）。slug・style・順序・リンク類は英語ビューに表示してはならない（SHALL NOT）。

英語ビューの「原文から翻訳し直す」ボタンは AI 翻訳でフィールド値を埋める（SHALL）。`author_en` は翻訳ボタンの対象にしてはならない（SHALL NOT）——手編集のみ。保存は人が保存操作で実行する（SHALL）——翻訳ボタン自体は正本に書かない。英語フィールドの保存は `_en` フィールドと `en_source_hash` **だけ**に触れる専用経路で行い、日本語側のフィールドを書き換えてはならない（SHALL NOT）。

#### Scenario: コースの英語ビュー

- **WHEN** コースメタビューを英語ビューに切り替える
- **THEN** `name_en` / `catch_en` / `description_en` / `target_en` の4入力と日本語原文の併記だけが表示される

#### Scenario: 翻訳ボタンは埋めるだけ

- **WHEN** 英語ビューで「原文から翻訳し直す」を実行する
- **THEN** フィールドに訳文が入るが、保存するまで `.meta.json` は変わらない

#### Scenario: author_en は自動翻訳されない

- **WHEN** レッスンの英語ビューで翻訳ボタンを実行する
- **THEN** `name_en` / `description_en` は埋まるが `author_en` は変わらない

### Requirement: 翻訳 API は stateless で Sonnet 5 固定・契約を注入する

翻訳 API（メタ・本文・changelog）は、AI の出力値を返すだけで正本に書き込んではならない（SHALL NOT）。モデルはワークスペースのモデル設定（`x-ai-model` ヘッダー・env）に関わらず **`claude-sonnet-5` に固定**しなければならない（SHALL）——費用のための決定。Fable 5 等を使う翻訳はスキル（Claude Code）経路が担う。プロンプトには `contracts/translation-contract.md` の全文を注入しなければならない（SHALL）。既存の英訳があるユニットでは既訳を入力に含め、「既訳を活かし必要な箇所だけ更新する」ことを指示しなければならない（SHALL）。

原文ハッシュ（本文のハッシュ行・メタの `en_source_hash`）は**サーバー側で計算**しなければならない（SHALL）——モデルに計算・生成させてはならない（SHALL NOT）。

#### Scenario: モデル設定に依存しない

- **WHEN** ワークスペースのモデル設定が別モデルの状態で翻訳 API を呼ぶ
- **THEN** 翻訳は `claude-sonnet-5` で実行される

#### Scenario: 正本に書かない

- **WHEN** 翻訳 API が成功する
- **THEN** `contents/` 配下のファイルは変更されていない

### Requirement: en 本文の読み書きはハッシュ行を API 境界で扱う

エディタに表示する `contents.en.md` の本文には原文ハッシュ行を含めてはならない（SHALL NOT）。保存（`language: "en"`）は既存ファイルのハッシュ行を保持したまま本文だけを差し替えなければならない（SHALL）——手動保存はハッシュに触らない。ファイルが無い状態での保存は、本文が空なら作成せず（SHALL NOT）、非空ならハッシュ行なしで作成する（SHALL）——手動翻訳は鮮度不明として stale 扱いになる（`translation-freshness` の規則）。本文の AI 翻訳の適用は、サーバーが計算したハッシュ行つきの完成形で保存しなければならない（SHALL）。

#### Scenario: 手動保存でハッシュが変わらない

- **WHEN** ハッシュ行を持つ `contents.en.md` を英語モードで編集して保存する
- **THEN** 本文は更新され、1行目のハッシュ行は保存前と同一である

#### Scenario: 空のまま切り替えてもファイルは生まれない

- **WHEN** `contents.en.md` が無いレッスンを英語モードで開き、何も入力せず離れる
- **THEN** `contents.en.md` は作成されない

#### Scenario: 本文翻訳の適用でハッシュ行が付く

- **WHEN** 英語モードの「本文を翻訳」を実行して結果を適用する
- **THEN** 保存された `contents.en.md` の1行目は現在の `contents.md` の原文ハッシュ行である

### Requirement: レッスンの本文翻訳ボタンはペイン2 ヘッダーの英語モードにだけ出る

「本文を翻訳」ボタンはペイン2 ヘッダー（鉛筆の並び）に置き、英語モードのときだけ表示しなければならない（SHALL）。エディタ本体（CodeMirror 側）に翻訳ボタンを置いてはならない（SHALL NOT）。

#### Scenario: 日本語モードでは出ない

- **WHEN** レッスンを日本語モードで表示する
- **THEN** 「本文を翻訳」ボタンは表示されない

### Requirement: ホームの英語ビューはメタと changelog を1ボタンで翻訳する

ホームの英語ビューでは、全体メタのフィールドと changelog セクション（`changelog.en.md`）が連動して切り替わらなければならない（SHALL）。翻訳ボタンは1つとし、全体メタの翻訳と changelog の追訳（英語側に無い新しいエントリの翻訳）を両方実行して、結果を分けて提示しなければならない（SHALL）。changelog の追訳は既存の英訳エントリを変更してはならない（SHALL NOT）——挿入はクライアントが行い、追記のみの担保は構造で持つ。

#### Scenario: 統合翻訳の実行

- **WHEN** ホーム英語ビューで翻訳ボタンを実行する
- **THEN** メタフィールドが埋まり、changelog の不足エントリの英訳が追記候補として提示される

#### Scenario: 片方の失敗が巻き込まない

- **WHEN** changelog の追訳だけが失敗する
- **THEN** メタフィールドの結果は使え、changelog 側のエラーが個別に表示される

### Requirement: 「最新として扱う」はハッシュだけを更新する

鮮度チップが「英語版が古い」のとき、「最新として扱う」アクションを提供しなければならない（SHALL）。実行は翻訳をせず、本文なら `contents.en.md` のハッシュ行を、メタなら `en_source_hash` を、現在の日本語側から再計算した値へ更新するだけとする（SHALL）。英語側が存在しない（未翻訳の）ユニットでは実行できない（SHALL NOT）。changelog には提供しない（SHALL NOT）——日付比較は追訳でしか解消しない。

#### Scenario: 手直し済みの英語版を最新化する

- **WHEN** 原文更新後に人が `contents.en.md` を手直しし、「最新として扱う」を実行する
- **THEN** ハッシュ行が現在の `contents.md` のハッシュになり、チップが消える

#### Scenario: 本文は変わらない

- **WHEN** 「最新として扱う」を実行する
- **THEN** `contents.en.md` の本文（ハッシュ行以外）は変更されていない

### Requirement: 鮮度状態は選択時に取得して表示する

鮮度状態は選択中のユニットについて API で取得し、選択変更・保存成功・翻訳適用・「最新として扱う」の後に再取得しなければならない（SHALL）。取得はロード API と分離し、正本への書き込み副作用を持ってはならない（SHALL NOT）。

#### Scenario: 保存後にチップが追従する

- **WHEN** 日本語モードで本文を編集して自動保存が走る
- **THEN** チップは再取得され「英語版が古い」に変わる
