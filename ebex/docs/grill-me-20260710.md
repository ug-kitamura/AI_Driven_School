# EBEX — グリルセッション記録（subtree 配布・ホストリポ構成）

**実施日**: 2026-07-10  
**目的**: EBEX を git subtree で複数ホストリポへ配布する際のフォルダ構成・ルート解決・スキル統合方針を固める  
**前提**: 会社内でリポ A / リポ B 等を新規作成。各リポは独自の `.claude/skills` を持つ。Cursor / Claude Code を持たない社員が EBEX からスキルを実行する  
**ステータス**: 主要決定済み ✅ / 未決事項あり（後述）

---

## 背景

- EBEX は **Cursor を持たない社員向けのスキル実行 UI** として、各ホストリポ（A, B …）に取り込んで使う。
- ホストリポにはルートに `.claude/`、`workspace/`、`openspec/` がある。EBEX リポにも同名フォルダがあるため、**配置と所有権の境界**を決める必要がある。
- 配布方式は **git subtree**。ebex リポを upstream とし、各ホストの `ebex/` 配下に取り込む。
- 将来的に EBEX 本体は 1 リポに統合する方向性はあるが、配布は subtree を維持する想定。
- 現状の EBEX 実装は `process.cwd()` を projectRoot としており、`.claude/skills/` と `workspace/` を **同一ルート** から解決している。ホスト配布では **appRoot と projectRoot の分離**が必要。

---

## 決まったこと

### 1. subtree の境界

| 項目                       | 決定内容                                                                                    |
| -------------------------- | ------------------------------------------------------------------------------------------- |
| **subtree に含めるもの**   | Next.js アプリ本体 + **製品用** `.claude/` + **製品用** `openspec/`（B 案）                 |
| **subtree に含めないもの** | ホスト固有の `workspace/`、ホスト固有の `.claude/skills/`、ホスト固有の `openspec/`         |
| **更新単位**               | subtree = 「EBEX 製品」の更新単位。`git subtree pull --prefix=ebex` で `ebex/` 配下のみ更新 |

### 2. 推奨フォルダ構成

**ebex リポ（subtree upstream）**

```
ebex-repo/
├── package.json
├── start.bat              ← 単体開発用
├── start.host.bat         ← ホストへコピーするテンプレート
├── ebe_purpose.md         ← EBEX 固有（appRoot 基準）
├── CLAUDE.md              ← アプリ開発ルール
├── .claude/skills/        ← 製品スキル（汎用名・接頭辞なし）
│   └── general-chat/      ← hidden
├── openspec/              ← 製品仕様
├── workspace/             ← gitignore（単体開発用のみ）
└── (Next.js アプリ本体)
```

**ホストリポ A / B（社員が使うリポ）**

```
repo-A/
├── start.bat              ← start.host.bat からコピー
├── CLAUDE.md              ← プロジェクト全体ルール
├── .claude/skills/        ← ★ 社員が使う主役スキル（ホスト接頭辞付き）
│   ├── A-grill-me/
│   └── A-minutes-maid/
├── openspec/              ← プロジェクト仕様
├── workspace/             ← ★ 社員の作業データ正本
│   └── 20260710-project/
└── ebex/                  ← subtree
    ├── ebe_purpose.md
    ├── .claude/skills/
    └── openspec/
```

### 3. appRoot / projectRoot の二層

| 概念                | 単体開発                               | ホスト配布                       |
| ------------------- | -------------------------------------- | -------------------------------- |
| **appRoot** (`cwd`) | `ebex-repo/`                           | `repo-A/ebex/`                   |
| **projectRoot**     | `ebex-repo/`（未設定時フォールバック） | `repo-A/`（`EBEX_PROJECT_ROOT`） |
| **workspace**       | `ebex/workspace/`                      | `repo-A/workspace/`              |
| **ebe_purpose.md**  | `ebex/ebe_purpose.md`                  | `repo-A/ebex/ebe_purpose.md`     |
| **ホストスキル**    | —                                      | `repo-A/.claude/skills/`         |
| **製品スキル**      | `ebex/.claude/skills/`                 | `repo-A/ebex/.claude/skills/`    |

| 項目               | 決定内容                                                                                     |
| ------------------ | -------------------------------------------------------------------------------------------- |
| **環境変数**       | `EBEX_PROJECT_ROOT` で projectRoot を明示（C 案）                                            |
| **フォールバック** | 未設定時は projectRoot = appRoot（A 案）。ebex 単体開発は従来どおり `ebex/workspace/` で動作 |
| **ebe_purpose.md** | EBEX 固有のため **appRoot 直下**（`ebex/ebe_purpose.md`）。`purpose.md` からリネーム予定     |
| **CLAUDE.md**      | **二層**: ホストルート = プロジェクト全体ルール、`ebex/CLAUDE.md` = アプリ開発ルール         |

### 4. workspace の所有権

| 項目        | 決定内容                                                                |
| ----------- | ----------------------------------------------------------------------- |
| **正本**    | **ホストルートのみ**（A 案）                                            |
| **subtree** | `workspace/` は含めない                                                 |
| **理由**    | subtree pull 時の上書き・衝突を避ける。ユーザーデータはホスト側に閉じる |

### 5. スキル統合

| 項目               | 決定内容                                                                                                      |
| ------------------ | ------------------------------------------------------------------------------------------------------------- |
| **読み込み元**     | ホスト `.claude/skills/` + ebex `.claude/skills/` の **両方**                                                 |
| **ebex 側の命名**  | **汎用名・接頭辞なし**（例: `general-chat`, `grill-me`）。製品として再利用しやすい名前をそのまま使う          |
| **ホスト側の命名** | **ホスト接頭辞を付ける**（例: リポ A なら `A-grill-me`, `A-minutes-maid`）。重複回避は **ホスト側の運用責務** |
| **衝突時（万一）** | 同一 `skill.id` が両方に存在した場合は **ホスト優先**（意図的上書きにも対応）。通常は接頭辞運用で発生しない   |
| **authoring 方針** | **B（部分互換）**: スキルは Cursor / Claude Code 向けに書き、EBEX では動く範囲で使う                          |

**命名の考え方**

- ebex のスキルは製品横断で共通の「辞書」として **短く汎用的な id** を維持する。
- ホストリポ A / B はそれぞれ **`{接頭辞}-` を付けたスキル**を `.claude/skills/` に置く。接頭辞はリポごとに固定（A リポ → `A-`、B リポ → `B-` 等）。
- EBEX の `/` オートコンプリートには **両方のスキルが並ぶ**。社員向けにはホスト接頭辞付きが主役、ebex 付属スキルは補助（例: hidden の `general-chat`）という分担が想定される。

```
ebex/.claude/skills/
  general-chat/       ← 製品（接頭辞なし）
  writing-proposals/  ← 製品（接頭辞なし）

repo-A/.claude/skills/
  A-grill-me/         ← ホスト（A- 接頭辞）
  A-minutes-maid/     ← ホスト（A- 接頭辞）
```

**スキルタイプと EBEX 互換性**

| タイプ                   | 例                           | EBEX                                     |
| ------------------------ | ---------------------------- | ---------------------------------------- |
| 対話のみ                 | grill-me, writing-proposals  | ほぼそのまま動作                         |
| workspace ファイル入出力 | 議事録生成、レポート草稿     | 動作（`@workspace/...` + 出力先選択 UI） |
| ツール依存               | create-draft（社内 DB 検索） | ツール未実装のため劣化                   |

**grill-me について（補足）**

- `tools:` frontmatter がないため、**チャット対話だけで完結**するスキル。
- Cursor の AskQuestion（選択肢ボタン UI）は EBEX にないが、**テキストで 1 問 + 推奨案**を返す形で同等の体験が可能。
- コードベース自動調査（Read/Grep/Glob）は EBEX エージェントツール未実装のため劣化。企画・設計の対話用途では問題になりにくい。
- **選択肢 UI** はまずテキストで始め、社員フィードバックを見てから判断（C 案）。

### 6. openspec

| 項目       | 決定内容                                              |
| ---------- | ----------------------------------------------------- |
| **方針**   | **完全分離、マージなし**（A 案）                      |
| **ホスト** | `openspec/` = プロジェクト固有の変更提案・仕様        |
| **製品**   | `ebex/openspec/` = EBEX 製品仕様                      |
| **理由**   | openspec はランタイム不要。subtree 更新との相性が良い |

### 7. 起動方法

| 用途              | 方法                                                                         |
| ----------------- | ---------------------------------------------------------------------------- |
| **ebex 単体開発** | `ebex/start.bat`（または `npm run dev`）。`EBEX_PROJECT_ROOT` はセットしない |
| **ホスト配布**    | `repo-A/start.bat`（`start.host.bat` をコピーしてカスタム）                  |

```bat
@echo off
cd /d "%~dp0ebex"
set EBEX_PROJECT_ROOT=%~dp0
set PORT=3001
call npm run dev
```

| 項目               | 決定内容                                                    |
| ------------------ | ----------------------------------------------------------- |
| **start.bat 本体** | ホストルートに置く（ホスト管理）                            |
| **テンプレート**   | `ebex/start.host.bat` を subtree に同梱。初回導入時にコピー |

### 8. subtree 更新運用

| 項目                   | 決定内容                                                                                               |
| ---------------------- | ------------------------------------------------------------------------------------------------------ |
| **自動化**             | **ebex リポの GitHub Actions が配信ハブ**（A 案）                                                      |
| **フロー**             | ebex `main` へ push → Actions が各ホストリポを checkout → `git subtree pull --prefix=ebex` → push      |
| **手動フォールバック** | 更新スクリプトを `ebex/scripts/` に同梱する案も検討可                                                  |
| **衝突回避**           | ホストは **`ebex/` を手編集しない**。カスタムはルートの `.claude` / `workspace` / `start.bat` に寄せる |
