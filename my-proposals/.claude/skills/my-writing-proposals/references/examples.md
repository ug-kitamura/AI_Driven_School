# 提案文書の例

意思決定者の問いに、結論ファーストで答えた提案文書。読み方は [SKILL.md](../SKILL.md) が扱う。

良かった提案文書は、見出しと本文を足すだけで増やしてよい。

---

## 在宅勤務を週2日に増やす

```
【提案】在宅勤務を週2日に増やすことを承認してください。来月から3か月の試験運用にしたいです。

◎ 現状の課題
通勤に往復2時間かかり、集中して作業する時間を確保しにくい。
資料作成は1人で進める作業が多く、出社の必要性が低い。

◎ 提案する理由
移動時間を作業に充てられ、締め切り前の残業を減らせる。
週2日に絞れば、対面が必要な会議や相談は出社日にまとめられる。

◎ リスクと対策
連携が滞らないよう、出社日を火・木に固定してチームで揃える。
3か月後に稼働と成果を振り返り、継続するか判断する。
```

## 採用管理ツールを導入する

```
【提案】採用管理ツールをHRtable（月額3万円）で導入したいです。
Googleスプレッドシートで管理している採用フローを移行する承認をお願いします。

◎ 現状の課題
選考状況の共有にメール往復が発生し、1件あたり平均30分かかっている。
スプレッドシートの更新漏れで、面接の重複が月2〜3件発生している。

◎ 他ツールとの比較検討
・HRtable（月額3万円）— 採用サイトとAPI連携できる
・Recruit Board（月額2万円）— API連携できないため見送り
→推奨：HRtable（連携で更新漏れと面接重複を防げる）

◎ コスト対効果
月額3万円に対し、現在の対応工数（月約20時間）を半減できる見込み。
```

## ノー残業デーを導入する

```
【提案】毎週水曜日をノー残業デーにしたいです。
定時の18時退勤を原則とすることを承認していただきたいです。

◎ 現状の課題
・定時以降は集中力が落ち、同じ作業でも時間がかかる
・平均残業時間は月40時間で、その時間帯の生産性は低い

◎ 提案する理由
・終わり時間を逆算することで生産性が上がる
・残業の常態化を防ぐことで離職リスクを下げられる
・週1回から始めることでまず効果を検証できる

◎ 補足
急ぎの仕事が入った場合は例外を認め、翌日に繰り越すルールとする。
```

## 問い合わせ当番を固定担当に変える

```
件名: 【提案】問い合わせ当番を2名の固定担当に変えさせてください

○○課長

■ お願い
問い合わせ対応の当番制を、来月から2名の固定担当に変えさせてください。
3か月試して、続けるかどうかを判断します。

■ 現状
当番は8名の輪番で、1人あたり月2回。
先月の対応記録では38件のうち24件が過去に同じ質問があったもので、
回答までの平均は4時間でした。

先週、私の当番の日に3年前の仕様について聞かれました。
当時の資料を探すのに1時間半かかり、その間その人の作業は止まったままでした。

■ 変える理由
輪番は、立ち上げのころに特定の人へ負荷が寄らないよう作られた仕組みです。
問い合わせが月10件程度だったころは、これでうまく回っていました。
いまは月38件まで増え、担当が毎回替わるため、同じ質問を毎回ゼロから調べ直しています。

固定にすれば、答えた内容が2名に蓄積されます。
過去の質問を覚えている人が答えるので、探す時間が減ります。

■ 進め方と判定
| 項目 | 内容 |
|---|---|
| 担当 | △△さんと私の2名（期間中の交代なし） |
| 期間 | 3か月 |
| 続ける基準 | 回答までの平均時間が2時間を切ること |
| 戻す基準 | 2名の残業が月10時間を超えたら輪番に戻す |

■ 懸念と対策
◎ 2名に負荷が集中する
1日あたり2件程度の想定です。戻す基準を先に決めておき、超えたら輪番に戻します。

◎ 2名以外が問い合わせ内容を知らなくなる
週次の朝会で、その週に多かった質問を2分だけ共有します。

3か月後に、平均時間と2名の残業時間を持ってご報告します。

○○
```

## 自作の社内AIツールをトライアル導入する

```
件名: 【提案】 EBEXを1か月トライアルさせてください

○○課長（△△部長にも共有）

■ お願い
自作のAIツール「EBEX」を、部内3名・1か月のベーシック版でトライアルさせてください。
EBEXはAIスキルを共有し、気軽に使うためのツールです。追加費用はゼロです。

決めていただきたいことは3つあります。
・3名・1か月のベーシック版トライアルの承認
・トライアルを始めることの、部長・他課の課長への共有
・テストユーザーを集めるための、部の月次会議での紹介（10分）

■ 背景と課題
便利なAIスキルを作っても、渡す手段がない。今いちばん詰まっているのはここです。
現状AIスキルの実行にはVSCode＋GitHub Copilotが必要です。
しかしCopilotには２つの問題があります。

問題1: 設定の難しさ
先日、Copilotの利用申請が通ったのに設定でつまずいた人が2人いました。
2人ともITリテラシーは高い方です。それでもつまずくなら、他の人はもっと苦労するはずです。

問題2: 導入のコスト
Copilotは個別の利用申請が要り、費用は1人あたり月30€からです。
より多く使いたい人は月100€と250€のプランもありますが、いずれも承認を得るのは難しいです。

■ 選択肢と費用

| 選択肢 | 導入の手間 | 月額 | 使えるモデル |
|---|---|---|---|
| VSCode + Copilot | 大 | 90€〜（30€×3名、人数に比例） | Claude Sonnet など様々 |
| EBEX ベーシック版 | 小 | 0€ | GPT-5 nano など軽量モデル |

EBEXベーシック版なら費用ゼロで始められます。

■ 進め方と判定

| 項目 | 内容 |
|---|---|
| 期間 | 1か月 |
| 人数 | テストユーザー3名 |
| 続ける基準 | スキルを実際に動かし、全員が業務の役に立つと感じてもらえること |
| 見直す基準 | 役に立たないと感じた場合。ただしモデルの性能不足が原因かは切り分けて判断します |

■ 懸念と対策

◎ ベーシック版は軽量モデルしか使えず、成果物の品質に限界がある
今回のトライアルで確かめたいのは品質ではなく、道具として配って使ってもらえるかどうかです。
品質が要る作業は、チーム版の要否を判断する材料として持ち帰ります。

◎ チーム版に移ると月150€+従量課金の費用が発生する
チーム全体の使用量が多い場合はCopilotより高くつくこともあります。
有償版の相談は、トライアルの結果を持って改めて伺います。

■ お願い（再掲）
・3名・1か月のEBEXベーシック版トライアルをご承認ください（追加費用なし）
・部長、他課の課長への共有をお願いします
・部の月次会議での紹介の機会をください（10分）

目指したいのは、一人ひとりが自分の手で効率を上げられる状態です。
その道具はもう手元にあります。まずは小さく、確かめさせてください。

○○
```
