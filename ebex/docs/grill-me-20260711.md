# EBEX — グリルセッション記録（ペイン1 ファイルツリー改善）

**実施日**: 2026-07-11  
**目的**: ペイン1（`FileTreePane`）の UI/UX 改善・バグ修正・お気に入り/内容検索機能の設計方針を固める  
**参考 UI**: Claude Code ファイルビュー（hover/選択色・右クリックメニュー）、Cursor ファイルエクスプローラー（階層縦線・テキスト揃え）  
**ステータス**: 主要決定済み ✅ / 未決事項あり（後述）

---

## 背景

ペイン1は `components/workspace/FileTreePane.tsx` が担当。`workspace/` 配下のフォルダ・ファイルをツリー表示し、選択・CRUD・DnD・名前フィルタを提供する。

ユーザーから以下 14 項目の改善要望があった。

| #   | カテゴリ | 要望概要                                                             |
| --- | -------- | -------------------------------------------------------------------- |
| 1   | UI       | フォルダ/ファイル hover 時にグレー系背景（Claude Code 同等）         |
| 2   | UI       | 選択ファイルの背景も hover と同じ色                                  |
| 3   | UI       | 選択ファイルのみ太字。フォルダは太字にしない                         |
| 4   | UI       | 右クリックメニューをシンプルに（削除も黒、hover は青にしない）       |
| 5   | バグ     | 検索クリア × ボタン：クリックで位置がずれる / 長押しでクリアされない |
| 6   | UI       | 検索ボックス右端をヘッダー右の追加ボタン右端に揃える                 |
| 7   | UI       | 縦スクロールバーをペイン2/3 と同じ `workspace-scrollbar` に          |
| 8   | 機能     | お気に入り（ファイルのみ、右クリック登録/解除、黄色 ☆）              |
| 9   | 機能     | 検索先頭 `?` でファイル内容検索（Claude Code 同等）                  |
| 10  | 機能     | お気に入りだけ表示 on/off トグル                                     |
| 11  | バグ     | フォルダリネーム後、旧名フォルダが残って見える                       |
| 12  | バグ     | 空フォルダ削除不可（`session.json` が存在するため）                  |
| 13  | バグ     | 外部（エクスプローラ等）での削除・リネームが EBEX に反映されない     |
| 14  | UI       | 階層縦線、フォルダ/ファイルのテキスト左位置揃え、chevron 小さめ      |

## 決まったこと

### 1. 実装フェーズ

| 項目        | 決定内容                                                                                                                    |
| ----------- | --------------------------------------------------------------------------------------------------------------------------- |
| **進め方**  | **2 段階**（A 案）                                                                                                          |
| **Phase 1** | UI 改善（1〜7, 14）+ バグ修正（11〜13）                                                                                     |
| **Phase 2** | お気に入り（8, 10）+ 内容検索（9）                                                                                          |
| **理由**    | 11〜13 はデータ同期・削除ロジックの修正。8〜10・9 は永続化・API が必要。先にペイン1の見た目と信頼性を揃えてから機能を載せる |

### 2. Phase 1 — UI（1〜7, 14）

| 項目                   | 決定内容                                                                                                                                                                                                       |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **hover / 選択背景**   | Claude Code 的なグレー。EBEX テーマトークン（`bg-muted` 系）で統一。hover と選択は**同じ色**                                                                                                                   |
| **太字**               | **選択中のファイルのみ** `font-semibold`。フォルダは太字にしない                                                                                                                                               |
| **右クリックメニュー** | 削除の赤文字・薄赤背景（destructive variant）は維持（Claude Code も同様のデザイン）。**通常項目**（ファイル追加・フォルダ追加・名前変更）の hover 時の青文字・青背景をやめ、ファイル選択時と同じグレーに揃える |
| **検索クリア ×**       | 位置ずれ・長押し不具合を修正（実装詳細は Phase 1 で対応）                                                                                                                                                      |
| **検索ボックス幅**     | 右端をヘッダー右のフォルダ追加ボタン右端に揃える                                                                                                                                                               |
| **スクロールバー**     | ツリー領域に `workspace-scrollbar` を適用（ペイン2/3 と同じ）                                                                                                                                                  |
| **ツリー構造**         | **両方の良いとこ取り**（C 案）: Cursor 風の**階層縦線 + テキスト左揃え + 小さめ chevron** + Claude Code 風の **hover/選択グレー**                                                                              |
| **chevron サイズ**     | 現状 `size-4` より一回り小さくしてよい                                                                                                                                                                         |

### 3. Phase 1 — バグ（11〜13）

#### 11. リネーム後に旧フォルダが残る

| 項目             | 決定内容                                                                                                                                                                                                             |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **原因（想定）** | `expanded` state のキーが旧 `folderPath` のまま残る、または React `key` とツリー再構築の不整合                                                                                                                       |
| **方針**         | リネーム成功時に `expanded` キーを `remapFolderPath` で更新。`onRefresh` 後のツリー key は新 path に揃える                                                                                                           |
| **確定**         | `expanded` の全キーのうち旧 `folderPath` に一致 or `旧folderPath/` で始まるキーを、既存の `remapFolderPath`（`workspace-tree.ts`）で新 path に置換する処理を `handleDialogConfirm` の `rename-folder` 分岐に追加する |

#### 12. 空フォルダ削除と session.json

| 項目       | 決定内容                                                                                                                  |
| ---------- | ------------------------------------------------------------------------------------------------------------------------- |
| **方針**   | **A 案**: `session.json` のみのフォルダも「空」とみなす                                                                   |
| **削除時** | フォルダ削除 API で **`session.json` も含めてフォルダごと削除**                                                           |
| **理由**   | EBEX 上では `session.json` は非表示の内部ファイル。ユーザーが「空フォルダ削除」した意図はプロジェクトフォルダごと消すこと |

現状の `isFolderEmpty` は `readdirSync` の件数 0 のみ判定しており、`session.json` があると非空扱いになる（`lib/workspace-paths.ts`）。

#### 13. 外部変更が反映されない

| 項目       | 決定内容                                                                                                                                          |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| **方針**   | **A 案**: 既存 **3 秒ポーリング**（`use-workspace-sync.ts`）を維持                                                                                |
| **修正**   | `getWorkspaceFingerprint` に**フォルダ構成（パス一覧）**を含める                                                                                  |
| **理由**   | 現状 fingerprint はファイル mtime のみ。フォルダ名変更・空フォルダ削除は mtime 変化なしで検知できない。chokidar 等の常駐監視は Phase 1 では見送り |
| **コスト** | 3 秒ポーリングにフォルダパス一覧を含めても、現状の workspace 規模では問題なし。上限・キャッシュ対策は不要                                         |

### 4. Phase 2 — お気に入り（8, 10）

#### 保存先（localStorage 却下）

| 項目     | 決定内容                                                                          |
| -------- | --------------------------------------------------------------------------------- |
| **却下** | localStorage — ブラウザキャッシュ削除で消える可能性があり困る                     |
| **採用** | **`workspace/.ebex-favorites.json`**（A 案）                                      |
| **配置** | workspace ルート直下に **1 ファイルのみ**（プロジェクトフォルダ単位では持たない） |
| **git**  | **gitignore 推奨**（個人ブックマーク）                                            |

```json
{
  "favorites": [{ "folderPath": "20260711-report", "fileName": "notes.md" }]
}
```

| 項目                | 決定内容                                                         |
| ------------------- | ---------------------------------------------------------------- |
| **対象**            | **ファイルのみ**（フォルダ不可）                                 |
| **操作**            | 右クリック → お気に入り登録 / お気に入り解除                     |
| **表示**            | ファイル名右端に黄色 ☆ アイコン                                  |
| **リネーム**        | EBEX 内リネーム時は API で favorites 内のキーを更新              |
| **外部削除**        | 次回読み込み時に存在チェックし、無効エントリは表示から除外       |
| **フィルタ UI**     | 検索ボックス**右端**に ☆ トグル（A 案）                          |
| **フィルタ × 検索** | **AND 条件** — お気に入り ON + 検索/query 両方に合うものだけ表示 |

### 5. Phase 2 — 内容検索（9）

| 項目             | 決定内容                                                                                             |
| ---------------- | ---------------------------------------------------------------------------------------------------- |
| **トリガー**     | 検索文字列先頭が **`?`** のとき内容検索モード                                                        |
| **通常検索**     | `?` なし — 現状どおりクライアント側ファイル名フィルタ（即時）                                        |
| **対象**         | workspace 内の**主要テキスト拡張子**を再帰検索（A 案）                                               |
| **拡張子（案）** | `.md`, `.txt`, `.json`, `.yml`, `.yaml`, `.ts`, `.tsx` 等 UTF-8 テキスト。バイナリ・`.next` 等は除外 |
| **タイミング**   | **300ms デバウンス** + サーバー API 非同期検索（A 案）                                               |
| **UX**           | 待ち中は「検索中…」表示（検索行下またはツリー上部）                                                  |

**リネーム ghost バグ（11）の手がかり**: `FileTreePane` の `expanded` state が `folderPath` 文字列キー。リネーム後 `onRefresh` しても旧キーが残ると展開状態が旧 path に紐づく可能性あり。`handleDialogConfirm` の `rename-folder` 分支で `expanded` の remapping が未実装。

**外部同期（13）の手がかり**: `collectWorkspaceMtimes` はファイルのみ walk。ディレクトリの追加/削除/リネームで fingerprint が変わらないケースがある。
