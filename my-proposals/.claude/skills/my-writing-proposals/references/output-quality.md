# 出力品質チェックリスト

提案文書を出力する前に、以下を満たすか確認する。満たさない項目があれば直してから出力する。

## 結論と構造

- [ ] 1行目が結論（＝相手へのお願い）になっている。要約で終わらず「だから何をしてほしいか」まで言い切っている
- [ ] 全体像 → 詳細の順になっている
- [ ] 事実・解釈・提案が混ざらず分かれている
- [ ] 情報が階層構造（◎ → ・）で整理され、同じ階層に同じ粒度の情報だけが入っている
- [ ] 選択肢を示す場合、主要な案を網羅したうえで推奨案を明示している

## 簡潔さと明確さ

- [ ] 「〜について」「〜の件」で逃げず、具体的なお願いになっている
- [ ] 一文が長すぎない（一文一義）。ただし削りすぎて意味が抜けていない
- [ ] 「品質」「早急に」など解釈の分かれる言葉に具体的な定義がある
- [ ] 同じ意味の言葉の表記揺れがない（用語が一貫している）
- [ ] 過剰な敬語で冗長になっていない
- [ ] 重要な数値や根拠が本文に書かれている（リンク頼みにしない）

## 仕上げ

- [ ] 箇条書きはMECE（漏れなく重複なく）で、語尾が統一されている
- [ ] 期限があるなら日時まで具体的（例：2026/07/01 17:00）。「予定」ではなく確定表現になっている
- [ ] 要点が1つだけの短い内容を、無理に階層化していない
- [ ] 意味の区切りで改行され、視覚的に読みやすい

## 型と絵

- [ ] どちらの型で書いたかが自分で説明できる
- [ ] ビジネス+ストーリー型なら、実際に見た場面が入っている。抽象語（非効率・重要・課題・改善）で済ませていない
- [ ] その場面はユーザーが語った事実で、AIが作ったものではない
- [ ] 絵で書き始めていない。結論が先に来ている
- [ ] 山場の絵が1つに絞られている。全部が山になっていない
- [ ] ビジネス型に縮退したなら、その旨をユーザーに伝えた
- [ ] 読み手の頭に浮かぶ懸念が、指摘される前に自分から出されている
- [ ] 読み手が複数いる場合、1人に焦点が合っている。他の読み手の関心は懸念で拾っている
- [ ] 決まった型を機械的に埋めた形になっていない。提案の中身に合った節構成になっている

## Purpose

- [ ] 織り込むなら1箇所だけ。繰り返していない
- [ ] 独立したセクションになっていない
- [ ] Purpose の言葉をそのまま引用せず、提案の文脈に言い換えている
- [ ] 接点がないのに無理に入れていない

## 出力形式

- [ ] 入力ファイルと同じフォルダに Markdown で保存した
- [ ] チャットにもコードブロックで出力した
- [ ] ファイル名から提案の内容が分かる
- [ ] 提案文書の中に太字などの markdown 装飾が入っていない
- [ ] 日本語で書かれている
- [ ] 最後にサブエージェントレビューを1行案内した（実行はしていない）
