# 翻訳契約（translation-contract）

DX トレーニング教材の翻訳規則。**日本語が正本、英語は派生**——翻訳は常に日本語 → 英語の一方通行で行う。この文書は Studio の翻訳機能と翻訳スキル（dx-training-translate）が共通で読む唯一の規則書である（規則の複製を他所に持たない）。

## 英訳するもの

- 本文のすべての文章（見出し・段落・箇条書き・表のセル）
- 画像プロンプトコメント（`<!-- ... -->` に書かれた画像生成の骨子）——英訳されたプロンプトから英語テキストの画像を生成し、英語版だけ差し替える運用があるため
- GitHub アラート（`> [!TIP]` / `> [!NOTE]` / `> [!WARNING]` 等）の中身
- コードブロック内の**コメント文**（`#` や `//` に続く説明）
- 画像の代替テキスト（`![代替テキスト](path)` の角括弧内）

## 変えないもの

- URL・リンク先
- 画像などのファイルパス・ファイル名（`images/<file>` の参照を書き換えない）
- コード本体（コマンド名・変数名・出力例の実行結果部分）
- Markdown の構造（見出しレベル・箇条書きの階層・表の列数・アラート種別）
- `> [!TIP]` などのアラート記法そのもの（キーワードは英語の仕様どおり維持）

## 迷ったときの作法

判断に迷う箇所（訳すと意味が壊れそうな固有名詞・社内用語・仮称など）は**無理に訳さず**、直後に執筆者向けコメントを残す:

```markdown
<!-- 訳注: 「DX Tools Training」は仮称のため原文のまま残した。確定後に差し替え -->
```

訳注はレビューで人が拾う前提の逃げ道であり、乱発しない。明らかに訳せるものは訳す。

## 触ってはならないもの

- `.meta.json` の `author` / `author_en`——人名のローマ字表記は本人の流儀。翻訳が書いてはならない（英語版の著者表記が必要なら人が `author_en` を手で入れる）
- `.meta.json` の `id` / `order` / `slug` / `cross_series_*` / `is_start` / `is_goal`——構造情報は翻訳の対象外
- 原文ハッシュ（本文1行目の `<!-- source: sha256:… -->` と `.meta.json` の `en_source_hash`）——翻訳の実行機構が計算して書く。モデルが生成・変更してはならない

## トーン

- 教材らしい平易な英語（学習者に語りかける、簡潔で親しみやすい文体）
- 原文の「です・ます」の丁寧さは、英語では自然なニュートラルさに置き換える（過度にフォーマルにしない）
- 原文の比喩・声かけ（RPG フレーム、セーブポイントのたとえ等）は意味が通る形で活かす
- 見出しは Title Case にせず Sentence case（先頭のみ大文字）

## 既訳があるときの規則（差分翻訳）

既に英訳が存在するユニットを再翻訳するときは、**既訳を読み取り、原文の変更に対応する箇所だけを更新する**:

- 変わっていない段落の訳文は一語も変えない（言い回しの一貫性と差分の小ささのため)
- 原文で追加・変更された箇所だけ訳し直す
- 用語集と既訳の言い回しが食い違う場合は用語集を優先し、その箇所だけ直す

## 用語集

訳語は以下で統一する（運用で育てる。追加は人が行う）:

| 日本語 | 英語 | 備考 |
|---|---|---|
| シリーズ | series | 教材の最上位階層 |
| コース | course | |
| レッスン | lesson | |
| 曼陀羅（曼荼羅） | Mandala | サイト名 DX Training Mandala に合わせ大文字 |
| 受講対象者 | intended audience | メタ表示は "For: ..." |
| 受講形態 | course style | self-study / lecture / hands-on は値のまま |
| 変更履歴 | changelog | |
| セーブポイント | save point | Git 比喩の中核語 |
| 三大エリア（Git） | the three areas | working tree / staging area / repository |
