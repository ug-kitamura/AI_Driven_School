# ebex-skill-contract Specification

## Purpose

スキル作者向け契約ドキュメント（制約と誓約）の正本・構造・必須収録項目。

## Requirements

### Requirement: スキル契約の正本

スキル作者向けの制約と誓約の正本は `contracts/ebex-skill-contract.md` でなければならない（SHALL）。パス解決は appRoot（ebex の設置ディレクトリ）基準でなければならず（SHALL）、projectRoot 基準で解決してはならない（MUST NOT）。契約はそれ単体で読んで従える内容でなければならず（SHALL）、EBEX 実装の内部仕様（ツール名・モジュール名・関数名）に依存してはならない（MUST NOT）。

#### Scenario: 契約が appRoot に同梱される

- **WHEN** EBEX リポジトリを clone する
- **THEN** `ebex/contracts/ebex-skill-contract.md` が存在する

#### Scenario: ホスト配下でも ebex 側を読む

- **WHEN** projectRoot が `host`、appRoot が `host/ebex` の状態で契約を参照する
- **THEN** 参照されるのは `host/ebex/contracts/ebex-skill-contract.md` であり、`host/contracts/` ではない

### Requirement: 制約の二層構造

契約は各制約項目を次の 2 群のいずれかに分類し、群ごとに作者への指示を変えなければならない（SHALL）。**A 群（ホストが吸収する制約）**: ホストが検出して代替手段へフォールバックする項目。作者は当該機能を用いる手順を書いてよく（MAY）、契約は当該機能の記述を禁じてはならない（MUST NOT）。作者への指示は「フォールバックされても手順が破綻しない形にすること」でなければならない（SHALL）。**B 群（どのホストでも守る作法）**: ホストが吸収できず、作者が守らなければ成果物が壊れる項目。作者への指示は必須（MUST）としなければならない（SHALL）。

契約は、スキルが EBEX 以外のホスト（Cursor・Claude Code 等）でも動くことを前提としなければならず（SHALL）、EBEX の制約を理由に他ホストで利用可能な機能を用いない設計を求めてはならない（MUST NOT）。

#### Scenario: A 群は機能の記述を許す

- **WHEN** 作者がサブエージェント・web 検索・画像処理を用いる手順を書く
- **THEN** 契約はそれを禁じず、フォールバック後も手順が完走する条件のみを求める

#### Scenario: B 群は必須として示される

- **WHEN** 作者が額縁テンプレートを持つスキルを書く
- **THEN** プレースホルダー規約・区間名の一意性・テンプレの自己完結・大きな成果物の断片差し込み・パスの役割語表記が必須として示される

#### Scenario: 群が判別できる

- **WHEN** 作者が契約の任意の制約項目を読む
- **THEN** その項目が A 群と B 群のどちらであるかが判別でき、対応する作者への指示が読み取れる

### Requirement: A 群の収録項目

契約の A 群は、少なくともサブエージェント・web 検索・画像／マルチモーダル・ファイル削除の 4 項目を収録しなければならない（SHALL）。各項目は、ホストが行う代替（フォールバック）と、作者が守るべき「破綻しない条件」を含まなければならない（SHALL）。

#### Scenario: サブエージェント項の内容

- **WHEN** 作者がサブエージェント項を読む
- **THEN** ホストが同一セッションでの順次実行へフォールバックすること、および並列性に依存した待ち合わせ制御を書かないことが読み取れる

#### Scenario: 画像項の内容

- **WHEN** 作者が画像・マルチモーダル項を読む
- **THEN** ホストがユーザーへスキップ／中止を選ばせること、および画像が欠けても成果物が成立する主線を持つことが読み取れる

### Requirement: B 群の収録項目

契約の B 群は、少なくとも次を収録しなければならない（SHALL）。短スロットは `{{XXX}}`、可変長ブロックは `<!-- XXX_START -->`〜`<!-- XXX_END -->` とするプレースホルダー規約。**区間マーカー名がファイル内で一意であること**。テンプレートの自己完結（CSS はインライン、小画像は base64）。大きな成果物はテンプレートを作業フォルダへコピーしてから断片を差し込むこと。場所は物理パスでなく役割（作業フォルダ・スキル相対パス）で書くこと。

#### Scenario: 区間名の一意性が必須として書かれている

- **WHEN** 作者が B 群を読む
- **THEN** 同一ファイル内に同名の区間マーカーを複数置いてはならないことが必須として示される

### Requirement: 契約の追加収録事項

契約は次の 3 点を収録しなければならない（SHALL）。**自動発火なし**: スキルはホストの明示指定（`/` による選択）でのみ起動し、作者はスキルから別スキルを呼ぶ連鎖を前提に手順を切ってはならない（MUST NOT）。**後処理の可否確認**: 英語版生成・レビュー・インライン化等の後処理工程に入る前に、実施するかスキップするかをユーザーへ尋ねること。**中間ファイルの置き場**: 中間ファイル（partial 等）は仮置き場フォルダに置き、成果物本体と混ぜないこと。

中間ファイルの置き場について、契約は具体的なフォルダ名を収録してはならない（MUST NOT）。実際の置き場はホストのランタイムが束縛するものとし、スキル作者がフォルダ名を決めて記述しない旨を読み取れるようにしなければならない（SHALL）。

契約の用語定義において「スキル同梱ファイル」の例には `references/` に加えて `assets/` を含めなければならない（SHALL）。

#### Scenario: 自動発火なしが作者向けの帰結として書かれている

- **WHEN** 作者が自動発火の項を読む
- **THEN** スキルから別スキルを呼ぶ連鎖を書かず、1 スキルで完結させることが読み取れる

#### Scenario: 後処理の可否確認が求められる

- **WHEN** 作者が英語版生成やインライン化を含むスキルを書く
- **THEN** 当該工程の直前にユーザーへ可否を尋ねる手順が必要であることが読み取れる

#### Scenario: 中間ファイルは仮置き場フォルダ

- **WHEN** 作者が中間ファイルの置き場を確認する
- **THEN** 成果物本体と混ぜない仮置き場フォルダに置くことが読み取れ、具体的なフォルダ名は記されていない

#### Scenario: 置き場の決定は作者の仕事ではない

- **WHEN** 作者が中間ファイルの項を読み、スキル本文にどう書くかを判断する
- **THEN** 置き場の具体名はランタイムが束縛するため、スキル側でフォルダ名を決めて書かないことが読み取れる
