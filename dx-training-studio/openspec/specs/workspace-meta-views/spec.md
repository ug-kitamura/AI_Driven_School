## Requirements
### Requirement: ペイン2 は選択階層に応じたビューを表示する

ペイン2（エディタペイン）は選択のフォーカス階層に応じて表示を切り替えなければならない（SHALL）:

| 選択 | 表示 |
|---|---|
| ホーム（全空） | 全体メタフォーム |
| シリーズ | シリーズメタフォーム |
| コース | コースメタフォーム＋ミニ曼陀羅 |
| レッスン | 従来のエディタ／プレビュー／差分 |

メタフォームはモーダルではなくペイン2 の全面に描き、ヘッダー行（階層名）とフォームと保存ボタンで構成する（SHALL）。

#### Scenario: シリーズ選択でペイン2 がフォームになる

- **WHEN** ツリーでシリーズを選択する
- **THEN** ペイン2 にシリーズメタフォームが表示され、エディタは表示されない

#### Scenario: レッスン選択は従来どおり

- **WHEN** ツリーでレッスンを選択する
- **THEN** ペイン2 に従来のエディタ（編集／プレビュー／差分）が表示される

### Requirement: 全体メタフォーム

ホーム選択時のペイン2 は、全体メタ（`contents/.meta.json`）の次のフィールドを編集できなければならない（SHALL）: **名前**・**説明**・**GitHub リンク**（URL）。ラベルは `名前`（`名前（サイト名）` ではない）とする（SHALL）。保存は本文右上の単一の保存ボタンで行い、空にしたフィールドは `.meta.json` からキーを削除する（SHALL）。GitHub リンクは URL 形式を検証し、不正なら保存を拒否する（SHALL）。

**ヒーロー画像を編集する UI を置いてはならない**（SHALL NOT）——実運用で変更されず、開くだけで画像一覧の取得を発生させていたため。⚠ `hero` フィールド自体と、`PUT /api/content/workspace-meta` での読み書き、公開サイト側の利用は**維持しなければならない**（SHALL）——`.meta.json` へ手で書けば従来どおり効く逃げ道を残す。

#### Scenario: サイト名と GitHub リンクを保存する

- **WHEN** ホームのフォームで名前と GitHub リンクを入力して保存する
- **THEN** `contents/.meta.json` に `name` と `github_url` が書き込まれる

#### Scenario: ヒーロー画像の項目が無い

- **WHEN** ホームの全体メタフォームを表示する
- **THEN** ヒーロー画像のセレクト・補足文・プレビューは表示されない

#### Scenario: 既存の hero が保たれる

- **WHEN** `hero` が設定された `.meta.json` でホームの名前を変更して保存する
- **THEN** `.meta.json` の `hero` は保存前の値のまま残る

#### Scenario: 不正な URL は拒否される

- **WHEN** GitHub リンクに URL でない文字列を入れて保存する
- **THEN** 保存はエラーになり `.meta.json` は変更されない

### Requirement: シリーズメタフォーム

シリーズ選択時のペイン2 は、**名前・説明・キャッチ・スラッグ**を**この順**で編集できなければならない（SHALL）。名前の変更は既存のリネーム経路（ディレクトリ名変更）を通す（SHALL）。スラッグ・キャッチ・説明はシリーズ `.meta.json` に保存し、空にしたフィールドはキーを削除する（SHALL）。スラッグは小文字英数とハイフンのみを受け付け、違反は保存を拒否する（SHALL）。保存時に `.meta.json` の他の既存フィールド（`id` / `order` / `_en` 系等）を消してはならない（MUST NOT）。

#### Scenario: フォームの並び順

- **WHEN** ツリーでシリーズを選択してペイン2 を表示する
- **THEN** 上からシリーズ名・説明・キャッチ・スラッグの順に並ぶ

#### Scenario: シリーズの slug と catch を保存する

- **WHEN** シリーズフォームで slug「git-basics」と catch を入力して保存する
- **THEN** シリーズ `.meta.json` に `slug` と `catch` が書き込まれ、`id` と `order` は保たれる

#### Scenario: 不正な slug は拒否される

- **WHEN** slug に「Git基礎」を入力して保存する
- **THEN** 保存はエラーになり `.meta.json` は変更されない

### Requirement: コースメタフォーム

コース選択時のペイン2 は、**名前・説明・キャッチ・スラッグ・受講対象者・受講形態・曼陀羅フロー**（同シリーズの前後表示、別シリーズの前後コース選択、Start / Goal 宣言）を編集できなければならない（SHALL）。曼陀羅フローの編集は既存の循環検出を通し、循環が生じる保存は警告して拒否する（SHALL）。スラッグの形式検証・空フィールドのキー削除・既存フィールドの保全はシリーズフォームと同じ規則に従う（SHALL）。

フォームの配置は次のとおりとしなければならない（SHALL）:

| 行 | 左列 | 右列 |
|---|---|---|
| 1 | コース名（全幅） | |
| 2 | 説明（**全幅**・3行の複数行入力） | |
| 3〜6 | キャッチ／スラッグ／受講対象者／受講形態（縦に順番） | ミニ曼陀羅（4行分の高さ） |
| 7〜 | 曼陀羅フロー設定（従来どおり） | |

説明の幅はコース名と同じ全幅としなければならない（SHALL）——シリーズ・レッスンの説明と揃える。

コースメタの項目追加時は、ローダーの保存要否判定（`listCoursesNeedingMetaPersist`）の比較にも同じ項目を追加しなければならない（SHALL）——比較漏れは「その項目だけの変更が保存されない」事故になる。

#### Scenario: フォームの並び順

- **WHEN** ツリーでコースを選択してペイン2 を表示する
- **THEN** 1行目にコース名、2行目に説明（全幅・3行入力）、その下の左列にキャッチ・スラッグ・受講対象者・受講形態が縦に並び、右列にミニ曼陀羅、最後に曼陀羅フロー設定が表示される

#### Scenario: 説明がコース名と同じ幅である

- **WHEN** コースフォームを表示する
- **THEN** 説明の入力欄の幅はコース名の入力欄と同じである

#### Scenario: コースの slug だけを変更して保存する

- **WHEN** コースフォームで slug だけを変更して保存する
- **THEN** コース `.meta.json` の `slug` が更新される（他フィールドの変更なしでも保存される）

#### Scenario: 循環する曼陀羅フローは保存できない

- **WHEN** 別シリーズの前後コース設定で循環が生じる組み合わせを保存しようとする
- **THEN** 警告が表示され、保存されない

### Requirement: コースビューのミニ曼陀羅

コース選択時のペイン2 には、当該コースを中心にしたミニ曼陀羅（サムネイル）を**フォーム右列（キャッチ〜受講形態の隣）**に表示しなければならない（SHALL）。グラフは**縦向き**（上から下への流れ）で描き、右列のセルに収める（SHALL）。**セルの高さは左列4項目（キャッチ〜受講形態）で決まり、グラフの実寸が左列の行間を引き伸ばしてはならない**（MUST NOT）——グラフはセルへ縮んで収まる（表示が小さくなるのは許容）。枠線は**サムネイル自身の枠1枚**とし、外側に追加の枠を重ねてはならない（MUST NOT）。ペイン1（ツリーペイン）にはミニ曼陀羅の固定領域を置いてはならない（MUST NOT）。

描画方式・ノード種別・辺の見た目・現在地の表現は `training-studio-mandala-render` に従う（SHALL）。サムネイルはパン・ズームを無効としなければならない（SHALL）。サムネイル上のクリックは、対象で以下のように分岐しなければならない（SHALL）。

- 隣接コースのブロックをクリックしたときは、拡大モーダルを開かずに、そのコースの編集画面へ直接遷移しなければならない（SHALL）。
- 中心（現在選択中）のコースのブロックをクリックしたときは、何も起きてはならない（MUST NOT）——遷移も拡大モーダルの表示も行わない。
- 上記以外の領域（余白・Start/Goal 端子・辺など、コースのブロック以外）をクリックしたときは、拡大モーダルを開かなければならない（SHALL）。

**拡大モーダル内のノードクリックで別コースへ遷移したとき、モーダルは開いたまま新しいコースのグラフに切り替わらなければならない**（SHALL）。

拡大モーダルの幅は、跨ぎ先が 3 つ以上あるコースでもグラフが収まる幅としなければならない（SHALL）。

#### Scenario: コース選択でペイン2 に曼陀羅が出る

- **WHEN** ツリーでコースを選択する
- **THEN** ペイン2 のフォーム右列にそのコースのミニ曼陀羅サムネイルが縦向きで表示される

#### Scenario: グラフが左列を引き伸ばさない

- **WHEN** ノード数の多いコースを選択してミニ曼陀羅が縦に長くなる
- **THEN** 左列4項目の行間は変わらず、グラフがセルの高さに合わせて縮小される

#### Scenario: モーダルからの遷移でモーダルが閉じない

- **WHEN** 拡大モーダルでノードをクリックして別コースへ遷移する
- **THEN** モーダルは開いたまま、遷移先コースのグラフに切り替わる

#### Scenario: 枠が一重である

- **WHEN** ミニ曼陀羅サムネイルを表示する
- **THEN** サムネイルの枠線は1枚だけで、それを囲う追加の枠は無い

#### Scenario: ペイン1 に曼陀羅は無い

- **WHEN** どの階層を選択していても
- **THEN** ペイン1 の下部にミニ曼陀羅の領域は表示されない

#### Scenario: サムネイルはパン・ズームできない

- **WHEN** ユーザーがサムネイル上でドラッグやホイール操作を行う
- **THEN** グラフはパン・ズームしない

#### Scenario: サムネイルで隣接コースのブロックをクリックすると直接遷移する

- **WHEN** ユーザーがサムネイル上の隣接コースのブロックをクリックする
- **THEN** 拡大モーダルは開かず、そのコースの編集画面へ遷移する

#### Scenario: サムネイルで中心コース自身のブロックをクリックしても何も起きない

- **WHEN** ユーザーがサムネイル上の中心（現在選択中）のコースのブロックをクリックする
- **THEN** 拡大モーダルは開かず、画面遷移も起きない

#### Scenario: サムネイルの余白をクリックすると拡大モーダルが開く

- **WHEN** ユーザーがサムネイル上のコースのブロック以外（余白・Start/Goal 端子・辺など）をクリックする
- **THEN** 拡大モーダルが開く

#### Scenario: 分岐が多くてもモーダルに収まる

- **WHEN** 跨ぎ先が 3 つ以上あるコースの拡大モーダルを開く
- **THEN** 全てのノードがモーダル内に収まって表示される

### Requirement: レッスンメタの編集入口

レッスンメタの編集はペイン2 ヘッダーの鉛筆ボタンから開くモーダルで行う（SHALL）。モーダルは既存フィールドに加えて**スラッグ**を編集できなければならない（SHALL。形式検証はシリーズと同じ）。ツリーの右クリックメニューに properties を置いてはならない（MUST NOT）——名前だけの変更は rename / F2 の `NameDialog` が担う。

#### Scenario: 鉛筆ボタンからスラッグを設定する

- **WHEN** レッスン表示中にペイン2 ヘッダーの鉛筆ボタンを押し、slug を入力して保存する
- **THEN** レッスンの保存済みメタに `slug` が書き込まれる

### Requirement: プレビューのメタラベル行

ペイン2 のプレビュー（inline）は、本文の上にレッスンメタのラベル行を表示しなければならない（SHALL）: 左から **状態**（未着手／作成中／完成）→ **所要時間** → **受講形態**（コースメタ `style` 由来）、右端に **著者**。デザイン（配色・形状）は公開サイトのレッスンページのラベル行と同一にする（SHALL）。値が無いラベルは出さない（SHALL）。編集・差分ビューには表示しない（MUST NOT）。

#### Scenario: プレビューにラベル行が出る

- **WHEN** status / estimated_minutes / author を持つレッスンをプレビュー表示する（所属コースに style あり）
- **THEN** 本文の上に 状態・所要時間・受講形態 のラベルと右端の著者名が表示される

#### Scenario: 編集ビューには出ない

- **WHEN** 同じレッスンを編集ビューで表示する
- **THEN** ラベル行は表示されない

### Requirement: ペイン2 ヘッダーの階層種別ラベル

ペイン2 のヘッダー行は、左端に選択中の階層種別ラベル（**全体／シリーズ／コース／レッスン**）を表示しなければならない（SHALL）。ラベルの体裁は4階層で同一とする（SHALL）——メタビュー（`MetaViewShell`）とレッスンのエディタビューで見た目を揃える。

#### Scenario: レッスン表示にも種別ラベルが出る

- **WHEN** ツリーでレッスンを選択してペイン2 にエディタを表示する
- **THEN** ヘッダー左端に「レッスン」ラベルが、メタビューの種別ラベルと同じ体裁で表示される

#### Scenario: 4階層でラベルが揃う

- **WHEN** ホーム・シリーズ・コース・レッスンを順に選択する
- **THEN** ペイン2 ヘッダー左端にそれぞれ 全体／シリーズ／コース／レッスン のラベルが表示される

### Requirement: メタビューのヘッダーは言語ビュー切替と鮮度チップを持つ

全体・シリーズ・コースのメタビューとレッスンのペイン2 ヘッダーは、言語ビュー切替（lucide `languages` アイコン）と鮮度チップを持たなければならない（SHALL）。レッスンでは鉛筆ボタンの横に置く（SHALL）。英語ビューの構成・チップの表示規則・編集言語の状態管理は `studio-translation` capability が正本である。日本語ビューの既存フォームの構成は変えない（SHALL）。

#### Scenario: 4階層で同じ操作感

- **WHEN** 全体／シリーズ／コース／レッスンをそれぞれ選択する
- **THEN** いずれのヘッダーにも言語切替が同じ見た目で表示される

#### Scenario: 日本語ビューは従来のまま

- **WHEN** 日本語ビューでコースメタビューを表示する
- **THEN** 既存のフォーム構成（スラッグ・キャッチ・受講対象者・受講形態・ミニ曼陀羅）が従来どおり表示される

### Requirement: メタビューの保存はヘッダーではなく本文右上に置く

ペイン2 のメタビュー（全体・シリーズ・コース）は、保存ボタンを**ヘッダーに置いてはならない**（SHALL NOT）。保存は**本文領域の右上**に置き、本文のスクロールに追従しなければならない（SHALL）。

この規則は日本語ビュー・英語ビューの両方に適用しなければならない（SHALL）——言語によって保存の位置を変えてはならない（SHALL NOT）。ヘッダーの右端は言語切替だけとする（SHALL）。

ボタン列に AI 操作を並べる場合は、**AI 操作を左・保存を右**の順にしなければならない（SHALL）。詳しい規則は `studio-translation` capability の「操作ボタンは本文右上の sticky なボタン列に置く」に従う。

#### Scenario: 日本語ビューの保存位置

- **WHEN** コースメタビューを日本語ビューで表示する
- **THEN** 保存ボタンは本文領域の右上にあり、ヘッダーには無い

#### Scenario: スクロールしても保存が見える

- **WHEN** コースメタビューで曼陀羅フロー設定まで下へスクロールする
- **THEN** 保存ボタンは画面に留まったまま操作できる

#### Scenario: ヘッダー右端は言語切替だけ

- **WHEN** 全体メタビューを表示する
- **THEN** ヘッダー右端には言語切替アイコンだけがあり、保存ボタンも鮮度チップも無い

### Requirement: ホームの保存は1つにまとめ、dirty なものだけ書く

ホーム（ペイン2）の保存ボタンは**1つだけ**でなければならない（SHALL）。1回の保存で全体メタ（`contents/.meta.json`）と変更履歴（`contents/changelog.md`、英語ビューでは `contents/changelog.en.md`）の両方を確定する（SHALL）。日本語ビュー・英語ビューのどちらでも同じ規則とする（SHALL）。

保存は**その保存で実際に編集された対象にだけ**書き込みを行わなければならない（SHALL）——編集していない対象へ書き込みを投げてはならない（SHALL NOT）。変更履歴は読み込み時点との mtime 突き合わせ（楽観ロック）を持つため、全体メタだけを直した保存が履歴の競合で失敗してはならない（MUST NOT）。

片方が成功し片方が失敗した場合は、両方の結果をそのまま提示しなければならない（SHALL）——成功した側を巻き戻してはならない（SHALL NOT）。

#### Scenario: 名前だけ直した保存は履歴に触らない

- **WHEN** ホームで名前だけを変更して保存する
- **THEN** `contents/.meta.json` だけが更新され、`contents/changelog.md` は読み書きされない

#### Scenario: 履歴だけ直した保存はメタに触らない

- **WHEN** ホームで変更履歴だけを編集して保存する
- **THEN** `contents/changelog.md` だけが更新される

#### Scenario: 外部変更があっても無関係な保存は通る

- **WHEN** 外部で `contents/changelog.md` が変更された状態で、ホームの名前だけを変更して保存する
- **THEN** 保存は成功し、履歴の競合エラーは表示されない

#### Scenario: 片方の失敗がもう片方を巻き込まない

- **WHEN** 全体メタと変更履歴の両方を編集し、変更履歴だけが外部変更で競合する
- **THEN** 全体メタは保存され、変更履歴の競合が個別に表示される
