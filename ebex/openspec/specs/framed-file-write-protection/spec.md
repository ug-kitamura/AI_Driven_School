# framed-file-write-protection Specification

## Purpose

額縁テンプレート（区間マーカーを持つ既存ファイル）への丸ごと上書きを検出し、額縁を保持したまま書き込む内容を中間ファイル置き場へ退避するための判定・退避規則。

## Requirements

### Requirement: 額縁ファイルの検出

システムは、書き込み先の既存ファイルが額縁テンプレートであるかを、ファイル内容の形のみから判定する純粋関数を提供しなければならない（SHALL）。判定条件は、対象パスに既存のファイルが存在し、かつその内容が区間マーカー組（`<!-- XXX_START -->` … 対応する `<!-- XXX_END -->`）を 1 つ以上含むこととする（SHALL）。区間の数・区間の中身が空か否か・ファイル拡張子を判定条件に用いてはならない（MUST NOT）。

判定にスキル ID・スキル名・実行モデル名を参照してはならない（MUST NOT）。マーカー組の検出は既存の区間マーカー検出（`replace-feedback` の区間パターン）と同一の規則でなければならない（SHALL）。

書込先が中間ファイル置き場（プロジェクトフォルダ直下の `_work/`）配下である場合は、内容に関わらず額縁ファイルではないと判定しなければならない（SHALL）。中間ファイル置き場は成果物を含まない使い捨ての領域であり、かつ退避先そのものであるため、ここを保護対象にすると退避が自己参照的に連鎖するためである。

#### Scenario: 単一区間の額縁を検出する

- **WHEN** 書き込み先が既存ファイルであり、内容に `<!-- CONTENT_START -->` と `<!-- CONTENT_END -->` の組が 1 つ含まれる
- **THEN** 判定は額縁ファイルであると返す

#### Scenario: 複数区間の額縁を検出する

- **WHEN** 書き込み先が既存ファイルであり、内容に `AGENDA_LIST` / `AGENDA_DETAILS` / `ACTION_PLAN` / `PURPOSE_CONTRIBUTION` の 4 つの区間マーカー組が含まれる
- **THEN** 判定は額縁ファイルであると返し、区間数によって結果が変わらない

#### Scenario: 区間が充填済みでも検出する

- **WHEN** 書き込み先の既存ファイルがすべての区間マーカー組を持ち、いずれの区間にも本文が充填されている
- **THEN** 判定は額縁ファイルであると返す

#### Scenario: マーカーの無いファイルは対象外

- **WHEN** 書き込み先が既存ファイルであり、区間マーカー組を 1 つも含まない
- **THEN** 判定は額縁ファイルではないと返す

#### Scenario: 新規ファイルは対象外

- **WHEN** 書き込み先のパスにファイルが存在しない
- **THEN** 判定は額縁ファイルではないと返す

#### Scenario: 中間ファイル置き場は保護対象外

- **WHEN** 書き込み先が `_work/` 配下の既存ファイルであり、内容に区間マーカー組を含む
- **THEN** 判定は額縁ファイルではないと返し、指定どおりのパスへ書き込まれる

#### Scenario: スキルによって判定が変わらない

- **WHEN** 同一内容の額縁ファイルに対し、異なるスキルの実行中にそれぞれ判定を行う
- **THEN** いずれの実行でも同一の判定結果が返る

### Requirement: 額縁への丸ごと上書きの退避

書込先が額縁ファイルであると判定された場合、システムは当該ファイルを丸ごと上書きしてはならない（MUST NOT）。代わりに、書き込む内容を中間ファイル置き場（プロジェクトフォルダ直下の `_work/`）配下の退避先パスへ書き込まなければならない（SHALL）。退避先のファイル名は元の書込先パスから機械的に導出し、同一の元パスに対して同一の退避先を返さなければならない（SHALL）。

退避は成功として扱い、エラーを返してはならない（MUST NOT）。tool_result には、退避が行われた事実・退避先パス・当該額縁へ差し込むための次の 1 手（`replace_between` に区間マーカーと `from_path` を与える）を含めなければならない（SHALL）。書き込む内容を破棄してはならない（MUST NOT）。

#### Scenario: 額縁は保持され内容は退避される

- **WHEN** 額縁をコピー済みの `output/bosch-company.html` を書込先として丸ごと上書きが試みられる
- **THEN** `output/bosch-company.html` の内容は変更されず、書き込む内容は `_work/` 配下の退避先へ書き込まれる

#### Scenario: 退避はエラーではなく成功として返る

- **WHEN** 額縁ファイルへの書き込みが退避される
- **THEN** tool_result はエラーではなく、退避先パスと `replace_between` による差し込み手順を含む

#### Scenario: 生成内容が失われない

- **WHEN** 子 LLM 生成を伴う書き込みが額縁ファイルを対象に退避される
- **THEN** 生成された本文は退避先ファイルに残り、再生成なしで差し込みに利用できる

#### Scenario: 退避先は決定的である

- **WHEN** 同一の書込先パスに対して退避が 2 回発生する
- **THEN** いずれも同一の退避先パスが用いられる

#### Scenario: 連続エラーによる停止を招かない

- **WHEN** 額縁ファイルへの書き込みが連続して 2 回退避される
- **THEN** 同一ツールエラーの連続とは扱われず、agent loop は停止しない

### Requirement: 全書込経路での共通適用

丸ごと上書きを行うツール（`write_file` / `generate_and_write` / `run_isolated_task`）は、書き込みの直前に同一の判定関数を呼び、額縁ファイルであった場合は同一の退避挙動を取らなければならない（SHALL）。ツールごとに判定条件・退避先の規則を変えてはならない（MUST NOT）。

区間を指定して部分置換を行うツール（`replace_between` / `replace_in_file` / `append_file` / `copy_file`）の挙動を変更してはならない（MUST NOT）。

#### Scenario: write_file でも退避される

- **WHEN** モデルが額縁ファイルを書込先として `write_file` を呼ぶ
- **THEN** 額縁は保持され、内容は退避先へ書き込まれる

#### Scenario: run_isolated_task でも退避される

- **WHEN** モデルが額縁ファイルを `path` に指定して `run_isolated_task` を呼ぶ
- **THEN** 額縁は保持され、結果は退避先へ書き込まれる

#### Scenario: 経路によって結果が変わらない

- **WHEN** 同一の額縁ファイルに対し `write_file` と `generate_and_write` がそれぞれ丸ごと上書きを試みる
- **THEN** いずれも同一の判定・同一規則の退避先で退避される

#### Scenario: 区間置換ツールは影響を受けない

- **WHEN** モデルが額縁ファイルに対して `replace_between` で区間へ差し込む
- **THEN** 退避は発生せず、従来どおり当該区間のみが置換される

#### Scenario: 中間ファイルへの書き込みは従来どおり

- **WHEN** モデルが区間マーカーを含まない `_work/` 配下の断片ファイルへ書き込む
- **THEN** 退避は発生せず、指定どおりのパスへ書き込まれる
