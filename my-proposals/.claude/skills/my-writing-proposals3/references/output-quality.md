# 出力品質チェックリスト

提案文を出力する前に確認する。満たさない項目は直してから出力する。

## 結論と依頼

- [ ] 件名（メールの場合）と1行目で「何をしてほしいか」が終わっている
- [ ] 結論が要約で止まらず、「だから何をしてほしいか」まで言い切っている
- [ ] 「〜について」「〜の件」で逃げていない
- [ ] 依頼事項が具体的で、読み手が何を承認すればいいか迷わない
- [ ] 締めで最初の結論が言い換えられ、依頼が残っている

## 絵

- [ ] 実際に見た場面が入っている。抽象語（非効率・重要・課題・改善）で済ませていない
- [ ] その場面はユーザーが語った事実で、AIが作ったものではない
- [ ] 絵の置き場が SKILL.md の「絵の置き場」に沿っている
- [ ] 読み手の頭に浮かぶ懸念が、指摘される前に自分から出されている

## 構成と材料

- [ ] 全体像 → 詳細の順になっている
- [ ] 判断に必要な数字・比較が本文にある
- [ ] 選択肢を示す場合、主要な案を網羅したうえで推奨案を明示している
- [ ] 相手が作った／続けてきたものを変える提案なら、状況変化として語られ、否定語が入っていない
- [ ] 決まった型を機械的に埋めた形になっていない。提案の中身に合った節構成になっている

## Purpose

- [ ] Purpose の扱いが SKILL.md の「Purpose の織り込み」に沿っている
- [ ] 接点がないのに無理に入れていない

## 文章表現

- [ ] [writing-essence.md](writing-essence.md) の各項目を満たしている
- [ ] 削りすぎて、意味の通る前提が抜けていない

## 形式

- [ ] コードブロックで出力している（ファイル保存を頼まれた場合を除く）
- [ ] 提案文の中に太字などの markdown 装飾が入っていない
- [ ] 日本語で書かれている
