# EBEX スキル契約（制約と誓約）

EBEX 向けにスキルを書く／直すときに従う契約。EBEX は軽量モデル＋作業フォルダ内に閉じた実行環境のため、通常のエージェントの一部機能が制限される。**このファイルはスキル作者向けの正本**であり、これ単体で読んで従える（実装の内部仕様には依存しない）。

スキルは EBEX 以外（Cursor 等）でも動くことを目指すため、本契約は**ホスト非依存で書けるように**促す。

## 用語

- **作業フォルダ** — 成果物を置く場所。EBEX 内部ではプロジェクトフォルダ（`workspace/<project>/`）を指すが、スキル本文では物理パスを書かず「作業フォルダ」と役割で呼ぶ。
- **スキル同梱ファイル** — `SKILL.md` と同じフォルダ配下（例: `references/`）のファイル。スキル相対パスで参照する。

## 制約と誓約（できない → 代わり → 書く時の注意）

### サブエージェント
- **できない**: サブエージェントの起動。
- **代わり**: 同一セッション内で役割を順に自ら実行する。
- **書く時**: 「サブエージェントに任せる」前提で分岐させない。1 つのエージェントが順に処理する手順として書く。

### web 検索
- **できない**: 自動 web 検索は原則不可（検索キーは既定で未設定）。
- **代わり**: 検索ワードを提示し、ユーザーが結果とソース URL を貼る。またはスキップして続行。
- **書く時**: 「検索して」で完結する手順にしない。人手入力を受け取る前提、または作業フォルダ内の資料を使う前提で書く。

### 作業フォルダの境界
- **できない**: 作業フォルダ外の読み書き（無断では不可）。
- **代わり**: 外部パスに触れる操作はユーザー確認を経る。
- **書く時**: 入出力は作業フォルダ内で完結させる。必要なファイルは事前に作業フォルダへ用意する前提で書く。

### 削除
- **できない**: ファイル削除。
- **代わり**: 不要物は残す（必要なら手動削除を案内）。
- **書く時**: 「一時ファイルを作って後で消す」設計にしない。中間ファイルは残っても無害な場所（成果物と同じフォルダの `_work/`）に置く。

### スクリプト実行とネットワーク
- **できない**: `run_script`（その場のコード）からの外部通信。作業フォルダ外への書き込み。
- **代わり**: ローカルのファイル変換はスクリプトで行える（確認のうえ実行）。外部データ取得が必要なら、審査済みのスキル同梱スクリプト（`scripts/` 配下）に置く。
- **書く時**: その場のスクリプトで `fetch` 等の通信を書かない。読取はスキル同梱ファイル基準、書込は作業フォルダ基準の相対パスで書く。

### 画像・マルチモーダル
- **できない**: 画像などマルチモーダルの生成・読取（入出力とも非対応）。
- **代わり**: 該当処理は非対応を通知し、スキップして継続するか中止するかをユーザーに委ねる。
- **書く時**: 画像生成・画像読取を必須ステップにしない。テキストで完結する手順を主線にする。

### MCP・外部コネクタ
- **できない**: MCP サーバ・外部コネクタの利用。
- **代わり**: 作業フォルダ内で完結する手段に置き換える。
- **書く時**: 外部コネクタ前提のステップを書かない。

### 大きな成果物
- **できない**: 巨大な本文を 1 回のツール引数に載せること（サイズ上限あり）。
- **代わり**: 額縁（テンプレート）があれば作業フォルダにコピーして断片を差し込む。創作長文は分割生成して差し込む。大量レコードはスクリプトで変換する。
- **書く時**: 成果物の形に応じて経路を 1 つ選んで書く（フォールバック列を並べない）。

### プレースホルダー
- **できない**: 挿入位置をモデルの判断に委ねる穴埋め（軽量モデルでは失敗しやすい）。
- **代わり**: 決定的に埋められる形（変数置換・区間差し込み）だけで完結させる。残留があるうちは「完了」にならない。
- **書く時**: 短スロットは `{{XXX}}`、可変長ブロックは `<!-- XXX_START -->`〜`<!-- XXX_END -->`。額縁内の自由記述コメントは書かない（指示は SKILL.md 側へ）。テンプレートは自己完結（CSS はインライン、小画像は base64）。

## パスと場所の書き方（ポータブル規約）

スキルを EBEX 以外でも動かすため、場所は**物理パスでなく役割**で書く。

- **コピー元** = スキル相対パス（`references/base.html` など）。`.claude/skills/…` や `workspace/…` と書かない。
- **コピー先・出力先** = 「作業フォルダ」等の役割語。物理パスを固定しない。
- **操作** = 意図の動詞（「コピーする」「埋める」「差し込む」）。ツール名（`copy_file` 等）を本文に書かない。ホストが実行時に適切なツールへ翻訳する。
- **「なぜ先にコピーするか」は書かない** — その必要性はホスト（EBEX）が実行時に補う。

### 例

推奨:
```
Step1: 額縁 references/base.html を作業フォルダにコピーする
Step2: コピーした額縁のプレースホルダー {{TITLE}} 等を埋める
```

避ける（ホスト依存で他環境で壊れる）:
```
Step1: references/base.html を workspace/<project>/output/ にコピー
Step2: copy_file で配置し replace_between で差し込む
```
