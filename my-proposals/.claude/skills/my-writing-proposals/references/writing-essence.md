# 文章表現のエッセンス

提案文書を書くときに適用する表現ルール。

構成・対話の進め方は [SKILL.md](../SKILL.md)、材料の集め方は [evidence.md](evidence.md) が扱う。ここは表現だけを扱う。

## 目次

- 結論先出し
- 1つの器に1つの仕事
- 一文一義
- 事実・解釈・提案の分離
- 推奨明示
- スコープ外の扱い
- 用語統一
- 数値と期限
- 記号と絵文字
- 相手のメンツを守る
- 書き方で変わる例

## 結論先出し

- 冒頭1行で結論（＝相手へのお願い）を言い切る
- 要約で終わらせず「だから何をしてほしいか」まで書く
- 読み手が3秒で判断できる状態を目指す
- 「〜について」「〜の件」で逃げない

## 1つの器に1つの仕事

件名・見出し・1文は、それぞれ1つのことだけを運ぶ。

- 件名に入れるのは最も重要な1件だけ。残りは本文が引き受ける
- 括弧で補足を足したくなったら、それは2件目のサイン
- 見出しも同じ。2つの話を1つの節に入れない

## 一文一義

- 1文は短く（目安30字）、1文に1つの意味
- 順接の「が」で本題を後ろに追いやらない。文を分ける
- 「しかし」「ですが」で対比せず、項目を分けて構造で示す
- 「また」「さらに」を重ねない。同種の情報が3つ以上並ぶなら箇条書きにする
- 列挙の前に「◯つあります」と数を伝える
- 意味の区切りで改行する。文の途中では改行しない
- 過剰な敬語（「恐縮ではございますが」等）は避け、簡潔な丁寧語にする
- 「おつかれさまです」等の前置きは省く

## 事実・解釈・提案の分離

- **事実**：数字・観測できる状態
- **解釈**：自分の判断・推測
- **提案**：相手に求める行動

3つを1文に混ぜない。混ざると、どこまでが事実か読み手が判断できなくなる。

## 推奨明示

- 選択肢を出すときは主要案を網羅し、`→推奨：◯◯（理由）` で締める
- 「どうしますか？」で逃げず、自分の意見を明確に示す
- 選りすぐりの1案だけを出すと、読み手は比較できず判断できない

## スコープ外の扱い

今回は求めないことを、否定形で断らない。肯定形で次に回す。

- ✗「今回はその判断を求めません」— 読み手の頭に、一度その負担が浮かぶ
- ○「有償プランの相談は、テスト結果を持って改めて伺います」— 求めないことが含意され、次の段取りも伝わる

そもそも触れるかどうかは、**読み手が後でそれを知ったとき、隠されたと感じるか**で決める。感じるなら書く。

## 用語統一

- 読み手が知らない固有名詞・専門用語は、初出で短く説明する。長い解説は要らない
- 同じ概念に複数の呼び方を使わない（例：ツール名・プラン名・「クライアント／顧客／お客様」）
- 箇条書きの語尾は、名詞止めか動詞止めのどちらかに統一する
- 箇条書きは漏れなく重複なく（MECE）

## 数値と期限

- 重要な数値・根拠は本文に直接書く。リンク頼みにしない
- 抽象語（品質・効率化・早急に）には、具体的な定義か数字を添える
- 期限は日時まで具体的に書く。「なるはや」「予定」を使わず、確定表現にする
- 番号リストは順序・手順のあるものだけに使う

## 記号と絵文字

- コロン（：）は見出し・定義の用途だけに使う
- 具体例は「例：」や引用記号（>）で本文と区別する
- 絵文字は多用しない。使うなら件名や強調点に限り、パターンを統一する（見出しだけ、または本文だけ）
- 見出しに1つだけ、本文にバラバラ、のような混在は避ける
- 箇条書きはMarkdown形式のハイフン（`- `）で書く。「・」は使わない

## 相手のメンツを守る

「変える・やめる」提案は、それを作った／続けてきた相手に「自分のやり方は間違っていたのか」と聞こえやすい。理屈が正しくても、ここでつまずくと通らない。事実は変えず、伝え方を整える（おだて・ごまかしは不可）。

- **過去を正当化する**：「当時は妥当だった」と置き、変更は"状況変化への対応"として語る
- **問題を人でなく状況・数字に帰属**：「やり方が悪い」でなく「事業が伸びて会議が増えた」
- **功績を立て、共同の前進にする**："あなた vs 私"でなく「これまでの仕組みを次の段階へ一緒に更新」
- **小さく・可逆にする**：試験運用や期間限定で、判断を全否定して覆す感を消す
- **否定語を避ける**：「無駄・非効率・間違い」を使わない
- **決定権は相手に残す**：最終判断は相手のもの、という姿勢で書く

対話では「この提案は相手が作ったもの／続けてきたものを変えるか？」を見極め、Yesなら上の配慮を強める。書き分けの例は「書き方で変わる例 → 過去を否定するかどうか」を見る。

## 書き方で変わる例

### 上流を埋めるかどうか

同じ「定例会議を減らしたい」でも、誰に・何を言い切るかを決めてから書くと結果が変わる。

**Before（上流が空っぽ）**

```
お疲れ様です。会議運営の効率化についてご提案がございます。
最近、会議時間の増加が生産性低下の要因として指摘されています。
つきましては、定例会議の頻度の見直しをご検討いただけますと幸いです。
```

丁寧だが、どの会議か・何がよくなるか・何をしてほしいかに答えていない。意思決定者は「それで？」となる。

**After（上流を埋めてから書く）**

```
【提案】報告だけの定例会議3本を隔週にして、浮いた月6時間を提案準備に充てます。ご承認をお願いします。

◎ 現状の課題
定例会議は週7本・延べ12時間。うち報告だけの3本が週3時間を占める。
直近の会議では発言者が7人中2人だった。

◎ 提案する理由
報告だけの会議は資料の前日共有で代替できる。議論のある会議は残す。
```

### 過去を否定するかどうか

同じ提案でも、過去を否定する書き方は通りにくい。状況の変化として語り、相手の功績を立てる。

**NG（過去を否定）**

```
今の定例会議は無駄が多く非効率です。やめるべきです。
```

**OK（状況変化＋功績を立てる）**

```
定例会議は立ち上げ期に足並みを揃えるのに役立ってきました。
人数も増えて自律的に動ける今、形を変えるタイミングだと思います。
まず1ヶ月、報告は資料共有に切り替えて試させてください。
```
