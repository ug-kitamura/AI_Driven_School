# turn-auto-continuation Specification

## Purpose

ターン終了3値判定・進捗ベース自動続行・プレースホルダー完了ゲート・継続診断ログ。

## Requirements

### Requirement: ターン終了の3値判定

ツール呼び出しなしでターンが `max_tokens` 以外の理由で終了した場合、システムは「ユーザー待ち / 完了 / 息切れ」を判定しなければならない（SHALL）。判定は次の優先順位で行わなければならない（MUST）: (1) 末尾に質問・確認依頼の形跡があればユーザー待ちとして停止、(2) 完了と判断できれば停止、(3) それ以外は息切れとして自動続行の候補とする。判定に迷う場合は停止側に倒さなければならない（SHALL）。

#### Scenario: 確認待ちを侵さない

- **WHEN** スキルのフローに従いモデルが「内容をご確認ください。問題なければ OK とお知らせください」で停止する
- **THEN** 自動続行は発火せず、ユーザーの応答を待つ

#### Scenario: 息切れの自動続行

- **WHEN** 軽量モデルが成果物の途中まで書いて「続きを作成します」等で自発的にターンを終える
- **THEN** システムが自動で続行を促し、ユーザーが「つづき」を入力することなく作業が再開される

### Requirement: 進捗ベースの続行制御

自動続行は進捗がある限り継続し、進捗がない場合に停止しなければならない（SHALL）。進捗判定は直前ターンとの出力重複と成果物ファイルの増分により行う。進捗なしの続行が 2 回連続した場合は停止しなければならない（SHALL）。総続行回数はプロファイルの `nudgeMax` を超えてはならない（MUST NOT）。

#### Scenario: 繰り返しループの防止

- **WHEN** 自動続行後の出力が直前ターンとほぼ同一で、成果物も増えていない状態が 2 回続く
- **THEN** 自動続行を停止し、現状をユーザーに提示する

#### Scenario: 暴走保険

- **WHEN** 進捗はあるが続行回数がプロファイルの `nudgeMax` に達する
- **THEN** 自動続行を停止し、上限到達をユーザーに知らせる

### Requirement: プレースホルダー完了ゲート

書込系ツール（copy_file / replace_in_file / replace_between / generate_and_write）の実行後、システムは対象ファイルの未置換 `{{XXX}}` プレースホルダーと空の `<!-- XXX_START -->`〜`<!-- XXX_END -->` 区間を検出し、残作業の一覧を tool_result に含めなければならない（SHALL）。検出ゼロの場合は完了の旨を含める。3値判定の完了確認にも同一の検出器を使用しなければならない（SHALL）。

#### Scenario: 残作業の明示

- **WHEN** copy_file でテンプレートをコピーした直後
- **THEN** tool_result に未置換プレースホルダーと未充填区間の一覧が含まれ、モデルが次に埋めるべき箇所を判断なしで特定できる

#### Scenario: 完了の確認

- **WHEN** すべてのプレースホルダー・区間が充填された状態で書込ツールが実行される
- **THEN** tool_result に残作業ゼロ（完了）が示される

#### Scenario: 規約外ファイルへの無害性

- **WHEN** プレースホルダー規約に従わない通常ファイルへ書込ツールを実行する
- **THEN** 検出はゼロ件となり、従来と同じ結果が返る

### Requirement: 継続診断ログ

システムは各ターンについて、モデル・stopReason・可視トークン数・自動継続/nudge の発火回数・完了ゲートの検出数を `.meta/diagnostics.log` に `type: "turn"` の JSON Lines レコードとして記録しなければならない（SHALL）。`.meta` が利用できない場合はアプリルートへのフォールバック出力を行わなければならない（SHALL）。ログ記録の失敗がエージェント動作を妨げてはならない（MUST NOT）。

#### Scenario: プロファイル調整の実測データ取得

- **WHEN** 新モデルで標準タスク（例: サンプル VTT での議事録生成）を 1 回実行する
- **THEN** ログから 1 ターンあたりの可視トークン数・継続回数・完了までの nudge 数が読み取れ、プロファイル値を実測ベースで決定できる

### Requirement: 自動続行の無効化スイッチ

自動続行（3値判定による nudge）は設定により無効化できなければならない（SHALL）。無効時は従来どおり `max_tokens` 継続のみが動作する。

#### Scenario: 問題発生時の切り戻し

- **WHEN** 自動続行の誤動作が疑われ、無効化設定で再起動する
- **THEN** nudge は発火せず、既存の max_tokens 継続のみで動作する
