# EBEX — グリルセッション記録（Agent ツール最小セット・安全ラップ）

**実施日**: 2026-07-12  
**目的**: EBEX Agent で Cursor / Claude Code 寄りのファイル作業（minutes-maid 等）を動かすための、最小ツールセットと安全境界を固める  
**きっかけ**: `minutes-maid` を EBEX で実行したが、ファイル未作成・途中切断・長大コンソールによるトークン不安が発生  
**前提**: 社員（IT リテラシーが低い利用者を含む）が EBEX からスキルを実行する。スキルは様々なユーザーが自由に作る  
**ステータス**: 主要決定済み ✅ / 実装は別セッションで OpenSpec proposal 予定  
**関連**: `grill-me-20260706.md`（出力・`on_conflict` 初期案）、`grill-me-20260710.md`（スキル互換・tools registry 空の認識）

---

## 背景

### minutes-maid 失敗の実態

`workspace/20260712-minutes/session.json` を確認した結果:

- モデルがチャット本文に偽の `<tool_call>` / `<tool_response>`（`read_file` / `write_file`）を生成していた
- `toolEvents` は常に空。実ツールは一度も実行されていない
- `output/` は未作成。`minutes.html` は 0 バイト
- 偽の読み書きログと巨大 HTML 断片が履歴に積み上がり、セッションが長大化
- ユーザーが「つづき」を連打しても、`max_tokens` 既定 **8192** で出力が切れ続けた

### 根本原因

```
minutes-maid 等 = Cursor / Claude Code 向け（Read/Write・大きな成果物）
        ↓
EBEX Agent = lib/agent/tools/registry.ts が空（本物の file I/O ツールなし）
        ↓
モデルがツールを演技 → ディスクに書かれない / トークン浪費 / 出力切断
```

`grill-me-20260710` 時点でも「registry は空」「authoring は部分互換」と認識済み。一方「議事録は `@` + 出力先 UI で動作」という設計意図と実装のギャップが、今回表面化した。

### 目指す水準

- **Cursor 全体の再現はしない**（サブエージェント・任意ターミナル・広範 MCP 等は対象外）
- **「作業フォルダの中で読んで書いて成果物を残す」** 体験は狙う
- 危険な操作はスキル frontmatter に委ねず、**EBEX ランタイムがラップして強制**する

## 決まったこと

### 1. 野心の境界

| 項目 | 決定内容 |
|------|----------|
| **狙うもの** | workspace 限定の発見・読取・書込 + 確認つき Web 検索 + 既存 agent loop |
| **狙わないもの** | サブエージェント、汎用シェル／スクリプト実行、任意コマンド |
| **判断基準** | 低リテラシー利用者でも、勝手に危険な副作用が起きないこと |

### 2. ツール能力層

| 層 | 能力 | v1 方針 |
|----|------|---------|
| **L0** | 対話のみ | 既存どおり |
| **L1** | 発見（list / glob / grep 相当） | **実装する**（既存内容検索 API 等への薄いラップ可） |
| **L2** | 読取（read_file） | **実装する** |
| **L3** | 書込（write_file / 必要なら mkdir） | **実装する** |
| **L4** | 削除（delete_file） | **ブロック**（実行しない） |
| **L5** | Web 検索 | **実装する**（都度確認） |
| **L6** | コマンド／スクリプト実行 | **ブロック**（実行しない） |

```
実装する          L0 / L1 / L2 / L3 / L5
ブロック＋案内    L4 / L6
```

### 3. ブロック時のユーザー案内（L4 / L6）

黙って失敗させない。意図が分かるメッセージを返す。

| 操作 | 案内に含めるもの |
|------|------------------|
| **削除（L4）** | 対象ファイルパス + ブロックした理由（EBEX では自動削除しない等）+ 手動削除の案内 |
| **コマンド実行（L6）** | 実行しようとしたコマンド全文 + ブロックした理由 + 必要ならユーザー自身のターミナルで実行する旨 |

例スキルへの影響:

- `uploading-surge`（PowerShell / `npx surge`）→ v1 はコマンド提示の劣化モードで十分
- 将来必要なら汎用 L6 ではなく、`deploy_surge` のような **許可リスト型の専用ツール**で救う（本セッションでは未決定・後続可）

### 4. Web 検索（L5）の確認

| 項目 | 決定内容 |
|------|----------|
| **確認粒度** | **都度確認**（クエリごと） |
| **確認文面** | 「『●●』というキーワードで Web 検索を実行します。よろしいですか？」 |
| **対象スキル例** | `creating-visual-explainers`（検索 2〜3 回） |

### 5. パススコープと確認ゲート

優先順位:

1. ユーザーが明示したパス → 候補にするが、プロジェクト外なら確認
2. スキル本文の入出力指示 → **プロジェクト内**の配置・ファイル名に効く
3. ランタイム既定 → 開いているファイルのプロジェクトフォルダ

| 操作 | 確認 |
|------|------|
| プロジェクト内 L1–L2 | 不要（サイズ上限のみ） |
| プロジェクト内 **新規** write | 不要 |
| プロジェクト内 **上書き** write | **必ず確認 → 同意で許可** |
| プロジェクト外 read | **要確認** |
| プロジェクト外 write | **要確認**（特に慎重。パス・新規/上書きを明示） |
| L5 web | **都度確認** |
| L4 / L6 | 実行せず案内 |

既存の送信前「プロジェクト外パス」ダイアログ・出力先選択 UI は、このモデルの芽として活かせる。

### 6. 上書きルール — スキル frontmatter に委ねない

| 項目 | 決定内容 |
|------|----------|
| **旧案** | スキル frontmatter `on_conflict: confirm \| overwrite \| skip`（`grill-me-20260706` / `ebex-agent-pane` spec） |
| **新方針** | **EBEX ランタイムが常に confirm を強制**。同意後のみ上書き |
| **理由** | スキルは多様なユーザーが自由に作る。設定漏れ・誤設定が多い前提。危険な選択はランタイムで潰す |
| **frontmatter** | `on_conflict` が書かれていても **無視してよい**（互換のため「無視する」と文書化する） |

信頼境界:

> スキルは自由に書ける。危険な選択は EBEX がラップして潰す。

### 7. 最大出力トークン — 設定側

| 項目 | 決定内容 |
|------|----------|
| **置き場所** | Workspace 設定（モデル・API キーと同列）。スキル frontmatter には持たない |
| **現状** | `anthropic.ts` で `max_tokens` 既定 **8192** 固定。agent-loop は上書き未渡し |
| **既定値** | **8192**（短文スキルの暴発防止） |
| **議事録・大きな HTML 用** | 設定で **32000** を選択可能にする |
| **UI 案** | 「最大出力トークン」— 選択肢例: `8192` / `16384` / `32000`（モデル上限でクランプ） |

大きな HTML はチャットに出さず `write_file` 経由にし、成功時の tool_result は短くする（下記）。

### 8. サイズ上限（minutes-maid 試運転向け）

今回の材料目安: VTT ~3.3 万文字、model-answer ~4.1 万文字。完成 HTML も同程度を想定。

| 項目 | 決定内容 |
|------|----------|
| **最大出力トークン** | 試運転・議事録は設定で **32000** |
| **read_file 上限** | 当面 **約 10 万文字**（VTT・base・完成 HTML が切れない余裕） |
| **grep / search** | 当面ゆるめ（例: ヒット 50 件）。minutes-maid 本命ではない |
| **write 成功時の tool_result** | パスとバイト数のみ。本文を履歴に戻さない |
| **方針** | まず動かしてから、実測で上限を締める |

トークン規律（ツール仕様に埋め込む）:

- 偽の `<tool_call>` テキストを書かせない（本物の tools を渡す）
- UI コンソールは要約表示（生の巨大 JSON を出さない）
- 履歴再送で古い巨大 tool_result を全文載せない（要約・省略）
- `model-answer.html` 全文の毎ターン読込はスキル側でも避ける（後続のスキル改善可）

### 9. スキル到達イメージ（本方針下）

| スキル | 見通し |
|--------|--------|
| `minutes-maid` | L1–L3 + 設定の出力 32k で本命に近づく |
| `creating-visual-explainers` | L1–L3 + L5（都度確認）で本命 |
| `uploading-surge` | L6 ブロック → コマンド提示の劣化モード |
| `grill-me` | L0、あれば L1–L2（コード調査は任意） |

## 確認ゲート一覧（最終）

```
プロジェクト外 read/write     → 要確認（write は特に明示）
プロジェクト内 新規 write     → 確認なしで可
プロジェクト内 上書き write   → 必ず確認 → 同意で許可（ランタイム強制）
削除 / シェル                 → ブロック（対象 or コマンド + 理由）
Web 検索                      → 都度確認（キーワード表示）
```
