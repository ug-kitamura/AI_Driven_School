# My Proposals

提案文書を、対話で材料を引き出して作るスキル置き場。

ベースはリポジトリ共通の `writing-proposals` を継承し、**読み手の頭に絵が浮かぶ具体を引き出す**ことを足した `my-writing-proposals` スキルとしてカスタマイズしている。

## 使い方

Cursor / Claude で次のように依頼する。

- 「提案文を作って」
- 「会社向けの提案を書いて」
- 「my-writing-proposals」

材料は最初にまとめて渡してよい（例: `my-issue.md`）。埋まっている項目は聞き返さず、不足分だけ確認してから出力する。

## ディレクトリ構成

| パス | 役割 |
|------|------|
| `.claude/skills/my-writing-proposals/` | カスタムスキル本体（`SKILL.md` + references） |
| `.claude/skills/my-writing-proposals1/`〜`3/` | 過去の試作。比較用に残している |
| `my-issue.md` | 検証用の課題・材料メモ |
| `proposals/` | 生成した提案文書 |
| `docs/` | grill-me 壁打ち記録・現状報告 |
| `openspec/` | スキル仕様（OpenSpec） |
| `writing-rule-example.md` | 文章ルールの原本 |

## スキルの要点

- 上流（誰に出すか／相手の問い／何を言い切るか／実際に見た場面）を対話で固めてから書く
- 6材料（変えたいこと・決裁者・相手の問い・根拠・**見た場面と心の声**・文体見本）を1問ずつ、推奨案つきで確認
- 骨格は PREP。結論を最初に言い切り、絵は根拠・背景の側にくどくない程度で差し込む
- 型は2つ。**ビジネス+ストーリー型が既定**で、絵の材料が出てこなければビジネス型に縮退し、その旨を伝える
- 分量・テンプレートで縛らない。長さは起動時か出力後に指示する
- Purpose / Mission を冒頭で1回確認し、1箇所だけさりげなく織り込む
- 出力は日本語。入力ファイルと同じフォルダに保存し、チャットにもコードブロックで出す

## 既知の課題

`my-writing-proposals1` / `2` / `3` が同じスコープに残っており、トリガーフレーズが本命と重なる。「提案文を作って」でどれが発火するか不安定になりうる。実運用に入る前に、試作の退避か description からのトリガー削除で整理する。
