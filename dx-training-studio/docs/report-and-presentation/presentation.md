プレゼン原稿
    1. はじめに
        私が作ったのは、DX ツールのトレーニングコンテンツを作成する、４ペイン ワークスペースです。
        ツール名を 「DX Training Studio」 に変えました。
    2. 解くべき課題
        何度も同じ説明で聞き飽きた方もいるかもしれないので恐縮ですが、、、
        会社で新しいプロジェクトが始まり、ツール環境が Git / GitHub に変わりました。
        でも、ほとんどのメンバーは Git / GitHub に慣れていなくて、理解度もバラバラです。
        なので 「受講者が自分のペースで独習できるトレーニングコンテンツを作りたい」 と考えました。
        私がこのスクールに入ったのは、この課題を解決したかったからです。
    3. どのデータを、どこに、なぜ保存したか?
        このツールは基本ローカルで動かすことを前提にしています。
        なので、作成したコンテンツは  GitHub に登録すれば十分と考えました。
        ただし「 画像」と「社内コンテキスト」は外部に保存しています。
        1. 画像の管理
            GitHub は大量の画像の置き場としては不適切 です。
            でも、コンテンツを公開することを考えると画像をローカルに置いておくわけにはいかない。
            そこで Vercel Blob ストレージを使うことにしました。
        2. 社内コンテキストの管理
            社内独自のプロセスやルールといったコンテキストをコンテンツに反映させたいと考えました。
            キーワードで必要な情報を検索して取り出す必要があります。
            そこで Vercel Neon データベースを使うことにしました。
    4. 工夫した点
        社内コンテキストの登録方法にひと工夫加えました。
        情報が膨大なので、そのまま登録しても再利用しづらいと考えました。
        そこで AI に要点を抽出させて、マークダウンに変換して登録するようにしました。
    5. 苦労した点
        ふと思い立って Claude Code のようなチャット画面を自作しました。
        ものすごく大変でしたが、、、AI と自然な対話をしながらコンテンツを作れるようにしました。
        スキルの呼び出しやファイルの参照もできるようにしました。
    6. さいごに
        感想
            AI がなんでもやってくれるためアイデアが次々に湧いてきます。
            AI で楽できるんですけど、やることも増えてしまって、トータルではかなり大変でした。
        今後は
            トレーニングコンテンツの原稿を書くスキルを５ヶ月目の課題で取り組みたいです。
            そして、トレーニングコンテンツの公開を卒業課題にしたいと考えています。
        ありがとうございました！
