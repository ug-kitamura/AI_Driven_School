# studio-changelog-editor Specification

## Purpose

Studio ホーム（ペイン2）の変更履歴編集の要件を規定する。正本 contents/changelog.md への手動編集を一次手段とし、AI 下書きは追記のみ・人の採否つきの補助に徹する。
## Requirements
### Requirement: ホームに変更履歴の編集入口がある

ホーム選択時のペイン2 は、全体メタフォームの GitHub リンク項目の下に変更履歴セクションを表示しなければならない（SHALL）。セクションは `contents/changelog.md` の内容を表示・編集でき、正本が存在しない場合は空の状態から作成を始められなければならない（SHALL）。

#### Scenario: ホームで履歴を開く

- **WHEN** ペイン1 でホームを選択する
- **THEN** ペイン2 の全体メタフォームの GitHub リンクの下に変更履歴セクションが表示され、`contents/changelog.md` の内容が見える

#### Scenario: 正本が無くても編集を始められる

- **WHEN** `contents/changelog.md` が存在しない状態で履歴セクションを開く
- **THEN** エラーにならず、空（または初期テンプレート）から編集を始められる

### Requirement: 手動編集で正本へそのまま保存する

編集内容は明示の保存操作で `contents/changelog.md` へそのまま書き込まなければならない（SHALL）。保存時に書式の検証・整形・並べ替えを行ってはならない（SHALL NOT）——書式は人の作法であり、Studio はそれを尊重する。

#### Scenario: 手で書いて保存する

- **WHEN** 履歴セクションでエントリを書き足して保存する
- **THEN** `contents/changelog.md` に入力どおりの内容が書き込まれる

#### Scenario: 書式は自由である

- **WHEN** 既存と異なる書式でエントリを書いて保存する
- **THEN** 警告や整形は行われず、そのまま保存される

### Requirement: AI 下書きは追記のみを生成する

AI 下書きは次の3点を材料としなければならない（SHALL）: (1) changelog 全文（基準点・重複回避・粒度と文体のお手本として）、(2) 基準日以降に更新（mtime）されたレッスン本文、(3) 現在のシリーズ・コース・レッスンのツリー。基準日の既定は changelog 先頭エントリの日付とし、日付が読み取れない場合は全レッスンを候補にする（SHALL）。

AI の出力は**新規エントリのみ**とし、既存の行を変更・削除してはならない（MUST NOT）。1回の下書きは、受講者にとって特筆すべき変更を最大5点程度に絞らなければならない（SHALL）。教材（コンテンツの中身・構成、受講者に価値のあるサイト変更）以外の変更を含めてはならない（SHALL NOT）。

#### Scenario: 下書きが先頭への追記として提示される

- **WHEN** [AI で下書き] を実行する
- **THEN** 新規エントリだけが生成され、既存エントリの本文は 1 文字も変わらない形の追記案として提示される

#### Scenario: 特筆点に絞られる

- **WHEN** 基準日以降に多数のレッスンが更新された状態で下書きを実行する
- **THEN** 提示されるエントリの項目は最大5点程度に絞られている

### Requirement: 矛盾は履歴ではなくメモとして提示する

AI が既存エントリと現状の食い違い（例: 追加と記録されたレッスンが現存しない）を見つけた場合、履歴本文に書き込んではならず（MUST NOT）、人向けのメモとして下書きとは別枠で提示しなければならない（SHALL）。直すかどうかは人が決める。

#### Scenario: 矛盾メモが別枠で出る

- **WHEN** 過去に「追加」と記録されたレッスンが削除された状態で下書きを実行する
- **THEN** 下書きエントリとは別に、食い違いを指摘するメモが表示される
- **AND** 履歴本文にはその指摘が含まれない

### Requirement: 下書きは差分で採否する

AI 下書きは即保存せず、現在の changelog との差分として表示しなければならない（SHALL）。人は差分を確認したうえで編集・承認・破棄でき、承認するまで正本を変更してはならない（MUST NOT）。

#### Scenario: 差分を見て編集して保存する

- **WHEN** 下書きの差分表示で文言を手直しして承認する
- **THEN** 手直し後の内容が changelog の先頭側へ挿入されて保存される

#### Scenario: 破棄できる

- **WHEN** 下書きを破棄する
- **THEN** `contents/changelog.md` は変更されない

### Requirement: 対象期間を指定し直せる

mtime による更新レッスンの絞り込みの基準日は、ユーザが指定し直せなければならない（SHALL）——clone や checkout の直後は全ファイルの mtime が更新され、既定の絞り込みが機能しないため。

#### Scenario: clone 直後に期間を絞り直す

- **WHEN** clone 直後（全ファイルの mtime が同時刻）に基準日を手動で指定して下書きを実行する
- **THEN** 指定した基準日以降に該当するレッスンだけが材料になる

### Requirement: 外部の変更を黙って上書きしない

保存時、読み込み時点からファイルが外部（エディタ・Claude Code 等）で変更されていた場合は保存を拒否し、外部の変更が失われないようにしなければならない（SHALL）。厳密な排他制御は要求しない——同一ローカルの道具同士の楽観ロック程度でよい。拒否時はユーザーに知らせ、再読込の手段を提供する（SHALL）。

#### Scenario: 外部変更を検知して保存を止める

- **WHEN** 履歴を開いたまま、外部のエディタで `contents/changelog.md` を変更し、その後 Studio で保存する
- **THEN** 保存は拒否され、外部で変更された旨が表示される
- **AND** 正本は外部の変更内容のまま保たれている
